## 2. 需要纠正的证据链

### F1：候选执行与候选证书不是同一输入序列

[`backup.expand_candidate`](../../../../experiments/paper_v3/baselines/backup.py) 把候选位置命令执行 **1 拍**，随后保持下一拍位置；[`fair_compare/common.py`](../../../../experiments/paper_v3/fair_compare/common.py) 的 `build_executed()` 却在候选被接受后将同一位置命令发布 **300 拍**，而 [`run_fair_compare.py`](../../../../experiments/paper_v3/fair_compare/run_fair_compare.py) 没有逐拍重新决策。55 个 trial 中 32 个使用这一候选回放，13 个候选回放记为 `false_safe`。现有结果混合了“单拍候选＋备份的预测”与“6 秒持续候选的执行”；不能直接把 13 个 `false_safe` 或这些 trial 的通行/误拒归因于 B1/B2 的证书。另有 6 个备份回放记为 `false_safe`，它们不受这个候选持续发布差异影响，但仍需在修订模型下重算。

**修正**：先固定唯一执行协议：每拍重新观测、重新决策；若转备份则持续发布备份命令。证书必须验证同一输入序列及全部延迟/误差分支。保留旧 55 个结果为历史探索材料，重新生成版本化结果。

### F2：N2 并未应用 N1 的辨识参数

[`04_fair_comparison.md`](04_fair_comparison.md) §2 已说明：N2 实际使用旧原型 `T_lag=0.85 s`、`L∈[0.15,0.25] s`；N1 得到速度通道 `T=0.2999 s`、位置沿向滞后 `1.1732 s`、`L∈[0.18,0.30] s`。速度与位置滞后属于不同模型量，不能直接互换；但旧原型也不能凭“记录了 N1 文件路径”就称已在选定接口上完成公平比较。特别是 N2 的真值延迟上界 `0.25 s` 低于 N1 区间上界 `0.30 s`。

**修正**：明确选择并独立验证可用于位置命令回放的模型；把 N1 的位置响应和延迟范围作为版本化参数输入，或将旧原型结论明确限定为合成算例。对模型误差保留校准范围，再以整次 run 的验证数据检查多步误差。

### F3：7 个固定延迟分支不覆盖任意时变延迟

[`probe.py`](../../../../experiments/paper_v3/history_probe/probe.py) 的 `proto_all` 和 `B2_baseline` 分别展开 7 个或 2 个**整个预测时域延迟恒定**的轨迹。报告中的两个时变场景只在第 160 拍跳变一次；其零覆盖违例只说明这两条轨迹在本批包络内，不能推出每拍可变时的可靠性。审查脚本沿用原模型、发布命令和允许的 9—15 拍延迟，在第 60 拍起的 50 拍内逐拍选取允许延迟，使末端位置为 `-0.483507547 m`；7 个固定分支的最大位置为 `-0.488584849 m`。超出约 `0.005077 m`，超过原探针的 `0.003 m` 低噪声覆盖容差。结果在 [13_review_checks.json](13_review_checks.json) 中可复算。

[`run_probe.py`](../../../../experiments/paper_v3/history_probe/run_probe.py) 将“两个单次跳变场景中全保留 0 违例”直接纳入 `no_independent_method_contribution=true` 的布尔判据。现在该判据的“可靠备选”前提不成立，不能用它证明一般时变延迟下的等价性或计算优势。停止当前剪枝实现仍合理，因为它在原负例中确实漏分支；论文新颖性还需要与已有集合辨识/鲁棒控制按算法定义和原文逐项比较，不能由五个模型场景的布尔值决定。

**修正**：先定义延迟的允许转移规律。若允许逐拍任意变化，传播每拍所有可能后继形成可达集合，或推导经验证的连续外包；用对抗性切换、单次跳变和固定延迟分别测试覆盖。端点 2 支不能未经证明充当一般时变延迟的安全基线。

### F4：“不伪造证书”被写成“已解决反例”

N2 的 `resolved.ce1_safe_handled_by` / `ce3_safe_handled_by` 只检查 `rule` 是否没有 `false_safe`。在 CE1 高速与 CE3 大延迟 trial 中，`rule` 的证书均为 `unavailable`，继续执行保持命令时仍分别有 22、7 拍违反设计裕量。这个结果是**正确报告当前状态不可认证**，并未展示从可行初态安全通过或安全停下。将其概括为“CE1/CE3 已解决”，再推出 `no_counterexample_requires_P=true`，证据强于实际观察。`04` §6 与 `06` §2 应改为“规则法能识别不可认证工况；是否有安全且可通行的标准解待修复后比较”。

## 3. 下一轮最小工作包与止损点

1. **先修离线证据，预计 2—4 个工作日。** 固定执行协议与评分分母；备份从每个允许延迟分支做全段净空检查，覆盖方向误差；对可行初态、不可行初态、候选转备份和连续重决策各加一个有辨别力的样例。让结果明确区分 `certificate_unavailable`、裕量违例、物理碰撞、误拒与通行。
2. **用辨识后的接口模型重新跑控制变量对照。** 同时保留原合成参数作为敏感性对照；测试 N1 延迟区间端点及内部值，并留出整次 run 的独立验证。每项“由标准方法解决”的判据应同时要求不虚报安全、在可行工况取得任务进展；不可行工况只报告不可认证。
3. **重做时变延迟覆盖检查。** 用 F3 的反例作必过样例；任何称作可靠的 B2 或全保留方案须覆盖允许的延迟切换及已声明扰动。用同一任务、同一预测范围和同一计算工作量计时；当前 `timing.json` 中原型和 `filters.decide` 的代码路径工作量不同，不据一次计时判定效率。
4. **再做一次 R0 决策，不直接进入 R1 或确认性实验。** 若修正后仍没有“标准强基线解决不了、且新机制在同覆盖/同预算下有稳定收益”的实例，正式终止当前 `P` 投稿主张。按 [`publication_plan.md`](../../publication_plan.md) §9.2，先给“计算预算下的安全过滤调度/约束筛选”做一页最近邻差异表和一个可证伪的小算例；若仍无独立贡献，转向与导师讨论改题。备选题也须重新检索，不自动认定可投稿。

[`06_r0_decision.md`](06_r0_decision.md) §4 提议的 **≤2 周 SITL 验证**此时不宜作为第一步：尚无一致的离线执行协议，且仅修标准备份并在一两个工况验证，不能直接判断“`P` 才能解决的剩余问题”。先完成上述修正，再为仍存的具体机制差异设计闭环试验。导师沟通可同步进行，带上本复审和可复算结果；本审查没有发送消息或代记导师意见。
