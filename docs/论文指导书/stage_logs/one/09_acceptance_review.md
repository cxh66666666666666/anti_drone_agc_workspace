## 3. 必须前置补正的内容

### F1：混淆了两个执行系统，且强基线设计退回旧模型

证据：

- `brake_hold_test.py` 顶部及 `run_mission()` 明确不启动 LQR，后台线程直接向 `/mavros/setpoint_position/local` 发布命令；制动是把位置设定点设成触发时的 MAVROS 位置。
- `03_b1_b2_design.md` §2.3 却把备份定义为 `/rl_planner/local_control` 的 `speed_scale=0`、`pause_progress=True`。原 LQR 节点据此冻结参考相位，并不自动把参考位置重置到当前实际位置；两者不能视作同一制动控制律。
- 该设计 §2.1—2.2 继续令 `max_offset_xy=1.4 m` 充当 `1.4 m/s` 并复用恒速动作预测；§3 又称 B2 与 B1 共享这一中心模型，同时加延迟状态，设计没有给出实际可递推的闭环方程。
- `06_research_decision.md` 与 `08_advisor_memo.md` 将 P 与 B2 的差异缩为误差集合/对 B1 的优势，偏离指导书已经要求的强方向相关 B2 与执行历史细化 P。

处理：根目录 **P0** 重写接口契约和方法对照。允许选择直接位置参考作为新系统，但必须明说替换了原外环，重新辨识；若保留原外环，则须在该链路验证相同的备份。对原位置接口的“暂时保留”可作预研选择，不能以当前台架数据宣告原组合闭环已验证。

### F2：制动采集/指标不足以支持冻结动力学参数

证据：

- `analyze()` 的 `max_drift_m` 是触发位置到尾段末即时位置的**净位移**；`tail_drift_m` 由相邻两次即时读取计算，不能表示尾段漂移。报告已主动标明这些问题，但采集代码和规范未同步修正，状态分类仍按错名指标判断。
- CE1 `sweep_peak_m` 计算的是沿给定方向的最大投影，报告中一处称“最大水平位移”。例如 long_03 沿向峰值 0.2302 m，水平径向峰值约 0.2306 m；量级接近不代表定义相同。
- 9 个 `ok` run 中 4 个 `use_sim_time=false`，5 个为 true。减去起始时间只消除起点，不能消除时钟速率差异。按巡航后半段位置变化与记录时间积分速度作粗查，比值约 0.9980—1.0013；**没有证据表明本批存在严重时基倍率失真**，但也没有源时间戳/独立 `/clock` 记录足以严格认证延迟与减速度。
- CSV 是对最新消息的轮询拼表；未分别保存 pose/velocity 的源时间戳、Gazebo 消息接收时刻与实际 setpoint 发布序号，且 MAVROS 位置和速度共用一个新鲜度更新时间。
- 报告的 0.18—0.20 s 是“采集脚本触发至速度下降 5%”的阈值响应时间，含响应动态，不能直接作为辨识出的纯运输延迟。
- 停稳判定用 Gazebo 速度可用于台架评分，但上线备份的控制状态转移不能依赖该真值。需要可观测状态与独立评分分离。

处理：**P1** 修订采集/指标协议与代码，保留旧 trace 为探索数据。下阶段只针对修订后的接口与时基补采必要样本，不删除旧失败，也不要求为文档标签错误重跑所有旧实验。新的统计统一从日志计算，区分沿向峰值、径向峰值、终态偏移、尾段最大偏移和稳态窗口起止。

### F3：公平制动结论没有对应实验；CE3 参数和输入不是实际位置指令

`fair_brake_compare.py` 对三个反例都直接写入 `with_brake_same_reach=True`，没有调用制动模型或展开两种控制器的候选＋备份轨迹；CE3 的 `survives=True` 更是常量。因此 `all_survive=true` 只能说明既有判断被汇总，**不能作为同等制动公平比较通过的证据**。

CE3 确实计算了一个一阶速度响应模型，离散结果与其解析式吻合；但 `V_CMD=1.4` 借自位置偏移上限，`TAU=0.85` 借自旧 z 轴位置阶跃，不能不经辨识直接用于横向速度环。其 `cruise_brake_replay()` 生成的是速度从 0.5 切至 0 的合成输入，没有读取真实 trace 的位置命令，也不能复现“回退到当前实际位置”的回摆行为。

CE2 的几何说明可以保留，但固定误差 `(0,0.2)` 不属于后面半轴为 `(0.2,0.05)` 的椭圆。前者是已知误差方向的例子，后者是给定不确定集合的最坏值；须分开表述，不能称同一批误差在同一覆盖集合内的实测优势。“净空 0.10 m 不满足 0.15 m 裕量”也不等于已经物理碰撞。

处理：**P2** 限定/更正文档结论，将现有公平汇总撤回为未验证，CE3 标为合成玩具例子。下一阶段 **N2** 实现独立、可证伪的同等制动对照；强基线解决全部反例是允许且有价值的结果，不要求反例必须存活。

### F4：未来预测协议混淆复现、辨识验证与反事实

`prediction_replay_format_v1.md` 有以下实质问题：

1. 用实际未来输入回放后要求与此前候选预测完全相等：只有候选确实被执行时才成立。动作后来被替换时应区分“候选复算”与“实际输入回放”，不能混为一项。
2. 要求预测与真值使用同一套延迟/滞后参数：这会排除模型误差验证，未知延迟下还可能泄漏真实注入值。控制器只能得到预定模型/估计范围；仿真注入参数单独给评分器。
3. 仅由段起点的 `|v_j|·dt/2` 就称保证采样间无漏碰：加速度或曲线运动时不成立。可在明确的**全段速度上界**下对两端采样给出相应余量，或直接做含运动外包的连续检查。
4. 把 `h(p)-σ_E(∇h)` 当作任意净空的等价鲁棒约束：仿射墙面可严格推导；一般非光滑/多障碍/弯曲几何需要逐约束分离面、余项界或保守集合相交检查。非对称误差集合还要核对支持函数方向。
5. 净空下界满足不能推出三维位置属于误差集合；`under_covered==0` 只是该批未发现下界违例，不足以证明一般安全。缺失、超范围、不同预测长度和轨迹相关性都要报告。

处理：**P3** 先修正文档格式，再实施回放。位置集合覆盖、净空下界违例、候选复算一致性分别报告；把真正的模型校准与独立验证分开。
