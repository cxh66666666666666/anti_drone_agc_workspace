## 2. B1 设计（标准标称预测安全过滤）

B1 是「标准做法」的最小落地：单点名义预测 + 离散 DCBF 判据 + 制动备份 + 相位/进度调节，**不含任何延迟增广或误差集合**（误差集合退化为 `E={0}`）。

### 2.1 状态与输入定义（对齐实际接口）

- **状态（观测）**：`p_k=(x,y,z)` 取 `/mavros/local_position/pose`（ENU）；`v_k=(vx,vy,vz)` 取 `/mavros/local_position/velocity_local`（世界系）。均为唯一真实链路中的物理量。
- **输入（动作）**：离散动作 `a∈{0..5}`，几何含义见 `safety_filter.ACTION_VECTORS`；映射到**运动帧**偏移 `(desired_left, desired_z)`，幅度由 `avoidance_magnitude(clearance, warning_distance_norm, min_offset_xy=0.3, max_offset_xy=1.4)` 给出，垂直步长 `step_z=0.3`。
- **真实执行接口**：动作最终落到两条话题——`/rl_planner/local_offset`（`Vector3Stamped`，map 系位置偏移）与 `/rl_planner/local_control`（`speed_scale, pause_progress, phase_direction`）。其物理落点是**位置设定点偏移**，经 LQR 跟踪器转成 PX4 位置设定点。
- **预测速度增量**（与现有过滤器一致）：横向 `lateral_speed = max_offset_xy = 1.4 m/s`，纵向 `vertical_speed = step_z = 0.3 m/s`；时域 `horizon_s=1.0 s`、`dt=0.1 s`。
- **一致性要求**：B1 的输入定义必须与上述偏移接口同一口径。现有代码「把偏移量上限当作速度」是设计假设，B2 的接口一致性主张会直接暴露该点（见 §5）。

### 2.2 点预测模型

复用 `safety_filter.predict_trajectory`：以当前 `p_k,v_k` 起，取动作 `a` 的定值速度增量（`action_velocity`），在 `horizon_s` 内等步采样，得名义轨迹 `P_nom(k,a)`。首样本即当前位置（与动作无关）。B1 明确记为**恒速名义点预测**，不含延迟/一阶滞后。

### 2.3 备份制动

B1 必须为每个候选动作提供「可保留制动退路」：在预测时域末端存在**制动档**把系统驱入制动可达集 `Ω_brake`。制动档定义为 `local_control` 的 `speed_scale→0` 且 `pause_progress=True`（比现有 `shield_escape` 的 `speed_scale≤0.3` 更彻底），参考速度置零。

- `Ω_brake = {速度模长 ≤ v_stop 且 与最近几何净空 ≥ clearance_floor 且 稳定窗口 ≥ T_hold}`。
- 制动触发的参考速度、`v_stop`、`T_hold`、尾段观察时长取自 `02_brake_hold.md` 的制动/保持规范（Task 2）。**该规范与其实测在本次撰写时尚未产出，相关阈值标「依赖 Task 2，待核验」**，不得用旧 `a_brake` p10（0.044 m/s²）顶替。

### 2.4 相位/进度调节

用沿路径进度 `s_k`（`project_path_progress`）与避障相位（进入/保持/脱离）调节判据松紧，**B1/B2 共用**：

- **接近相位**：提前收紧 margin 或提前触发备份，防止滞后后没退路；
- **脱离相位**：复用现有尾部 gate（`avoidance_tail_gate`、`locked_avoid_side`）在障碍刚通过后不急于切回标称，避免窄通道误拒绝；
- **相位方向**：沿用 `local_control` 的 `phase_direction`。

### 2.5 约束判据与终端条件

- **判据**：复用 `safe_action_set` 的离散 DCBF 形式——对每个采样转移 `Δh + α·h ≥ ε_pred`（`h=clearance−margin`，首样本不参与判据，因为与动作无关）。此形式与综述的 DCBF 及 Layered Safety 的 `h(ξ_{i+1}) ≥ ρ h(ξ_i)` 同构。
- **终端条件**：在 B1 中为「稳态冗余」——仅要求名义预测时域末端落入 `Ω_brake`，即存在制动退路。判据 `h≥0` 与终端可达集共同构成「制动退路可保留」的证书。

### 2.6 超时与证书失效处理

- `A_safe` 为空：**不直接 `done`**，先转备份制动（改进现有 `empty_safe_set_termination` 立即终止的做法）。
- 制动后超过 `T_brake_max` 仍未达 `Ω_brake`：记 `shield_infeasible`。
- 传感器失效 / 观测陈旧（`obstacles` 陈旧 > `perception_timeout`）：保守转保持/制动，标 `certificate_invalid`。
- `local_offset`/`local_control` 命令超时未确认执行：证书降级（B2 的延迟增广状态依赖已发布命令序列，见 §3）。

## 3. B2 设计（延迟增广、方向相关的鲁棒预测安全过滤）

B2 在 B1 之上**只改一处**：把单点名义预测换成「延迟增广状态 + 方向相关误差集合 + 集合传播」的鲁棒预测。中心预测、参数范围、输入权限、校准数据、备份、相位调节**全部与 B1 共享**。

### 3.1 延迟增广状态

定义增广状态 `x̄_k = (p_k, v_k, a_{k-1}, …, a_{k-τ})`，其中 `τ = ceil(τ_exec/dt)` 由辨识得到。可用的辨识量（冻结于 `control_validation_protocol_v1.md`）：阶跃纯延迟 `0.24/0.24/0.28 s`、时间常数 `0.85/0.85/0.80 s`，表观反应时间 `tau_react=0.84 s`；实验协议 `position_lead_time=0.80 s`（节点默认 `0.02 s`）。命令历史取自已发布的 `/rl_planner/local_offset` 与 `/rl_planner/local_control` 序列——即在预测中显式携带「尚未生效的指令」，这是 B1 恒速点预测缺失的一步。

### 3.2 方向相关误差集合（支持函数 σ_E(n) 形式）

用集合 `E⊂R^3` 表示闭环实际位置相对名义预测点的可达偏差，**方向相关**（各向异性），并以支持函数刻画：

`σ_E(n) = max_{e∈E} n·e`（`n` 为单位方向）。

- 误差集合由辨识残差**按方向分箱**（前向/侧向/纵向）标定，横向与纵向分别给不同尺度，避免各向同性大球导致的过度保守（各向同性大球仅作弱化消融）。
- 鲁棒约束收紧：要求 `h(p+e) ≥ 0, ∀e∈E`，等价地按 `∇h` 方向收紧为 `h(p) − σ_E(∇h) ≥ margin`（对几何净空用带符号支持函数近似）。
- 支持函数形式便于与 zonotope/区间盒对接（集合的 Minkowski 和对应支持函数相加），也便于在 `n` 方向上给出保守但方向精确的收紧量。

### 3.3 集合传播（区间盒 / zonotope）

- 传播模型：`p_{i+1} ∈ p_i + (v_i + Δv(a))·dt + W_i`，其中 `W_i` 由**延迟不确定**（`τ` 的区间）与**一阶滞后不确定**（`tau`、`position_lead_time` 的区间）传播得到。
- **区间盒**：轴对齐盒，最简，支持函数解析、易落地（首版实现选它）。
- **zonotope**：保留方向相关性，收紧更紧；支持函数仍可解析。作为精度升级档。
- 传播后得到鲁棒可达集 `R(a)`，其支持函数用于 §3.2 的收紧判据。

### 3.4 备份与相位调节（与 B1 共用）

备份制动、`Ω_brake`、`T_brake_max`、相位/进度调节与 B1 **完全相同**；差别仅是判据中的 `h` 换成鲁棒收紧后的 `h_rob = h − σ_E(∇h)`。即「制动退路」在 B2 中也是以同一集合口径判定可达。

## 4. B1 与 B2 的差异声明

**两者只差一项**：误差集合的表示（以及由此明确提出的新增步骤）。

| 组件 | B1 | B2 |
|---|---|---|
| 误差集合 | 单点 `E={0}`（无集合） | 方向相关集合 `E(n)`，支持函数 `σ_E(n)` |
| 新增步骤 | 无 | 延迟增广状态 + 集合传播（区间盒/zonotope） |
| 中心预测 | **共用**（同一 `predict_trajectory` 与动作速度增量） | **共用** |
| 参数范围 | **共用**（`horizon_s/dt/α/ε_pred/margin/速度增量`） | **共用** |
| 输入权限 | **共用**（同一 6 动作 + 制动档） | **共用** |
| 校准数据 | **共用**（同一辨识批次） | **共用** |
| 备份制动 | **共用** | **共用** |
| 相位/进度调节 | **共用** | **共用** |

这一差异正是本项目候选贡献的载体：「执行接口一致的预测 + 方向相关误差表示」如何改变安全—效率边界。任何超出上表「误差集合/新增步骤」之外的差异都不属于 B1↔B2 的合法差异。

## 5. 与现有代码的接口约定

### 5.1 直接复用（只读，不改）

- `safety_filter.predict_trajectory` / `action_velocity`：名义点预测与动作速度增量。
- `safety_filter.safety_function`：`h = clearance − margin`。
- `safety_filter.safe_action_set`：离散 DCBF 判据（`Δh+αh≥ε_pred`），B1 的判据内核。
- `safety_filter.predicted_clearance` / `predicted_horizon_gain` / `clearance_improving_actions` / `escape_action` / `best_effort_action`：净空评估与逃逸/兜底。
- `safety_policy.select_filtered_action` / `modulated_margin` / `held_action` / `action_geometry_cost`：动作选择、裕量调制、保持窗口、偏离代价。
- `geometry_metrics.minimum_geometry_clearance`：几何净空。
- 环境侧驱动：`gazebo_env._publish_action_motion` / `_publish_offset` / `_publish_local_control`；话题 `/rl_planner/local_offset`、`/rl_planner/local_control`。

### 5.2 必须替换或修改的假设（B1/B2 的落地阻塞点）

1. **恒速预测**：`predict_trajectory` 用「当前速度 + 定值动作增量」恒速外推，未建模纯延迟/一阶滞后。B1 保留该假设但须显式声明为「名义点预测」；B2 必须改为延迟增广 + 集合传播（新增代码，不改旧函数以保持旧结果语义）。
2. **真值辅助障碍**：`gazebo_env._safety_obstacles()` 用 `scenario_obstacles_typed`（或障碍中心+尺寸）构造形状，仅按当前扇区最小距离门控，**不是从点云重建**。这对「纯 LiDAR、未知环境」主张属特权几何。B1/B2 需另设「纯局部感知」输入入口（B2 的「接口一致」主张尤其依赖此项）。
3. **无制动档**：`ACTION_VECTORS` 六动作里没有停/减速动作（动作 0 是 nominal reference velocity）；`best_effort_action` 兜底也不减速。后果：`safe_action_set` 判据无制动候选，正对障碍接近时易判空集，备份制动**无法表达**。B1/B2 需新增制动/保持通道（参数来自 §2.3 的制动规范）。
4. **速度增量口径**：现有过滤器把 `max_offset_xy=1.4` 当横向速度、`step_z=0.3` 当纵向速度（偏移上限≈速度），与「位置设定点偏移」真实接口不同一口径。B2 的接口一致性要求会把该口径差异显性化。
5. **终止逻辑**：`empty_safe_set_termination` 立即置 `done`，随后 `_publish_offset(0,0,0)` 并复位，**未证明已停稳**。B1/B2 的终端/超时处理须在终止前转入制动并持续观测（`Ω_brake` 稳定窗口），把「任务失败判定」与「物理观测结束」分离。
6. **交叉验证只证实现一致性**：`stage3_task5_cross_validate.py` 只比较预测时域最小值与当前几何净空，且预测轨迹含初始点，故「预测最小净空 ≤ 当前净空」本应成立。它**不能证明未来真实轨迹被覆盖**。B1/B2 的证书失效/预测回放需新的「对齐预测发出时刻 + 实际执行输入 + 未来观测」验证格式（Task 4）。
