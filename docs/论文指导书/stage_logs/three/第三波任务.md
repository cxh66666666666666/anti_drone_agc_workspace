# 第三波任务：验证替代方法是否值得继续

> 制定日期：2026-09-25。上一波任务存档在 [`two/publication_tasks.md`](../two/publication_tasks.md)；决策依据为 [`two/17_followup_review.md`](../two/17_followup_review.md)、[`two/14_offline_protocol_and_comparison.md`](../two/14_offline_protocol_and_comparison.md) 和 [`two/15_time_varying_coverage.md`](../two/15_time_varying_coverage.md)。总体投稿目标与质量门槛仍见 [`publication_plan.md`](../../publication_plan.md) §9.2、§12。
>
> **状态：待执行。期限：最多 5 个工作日、主动研究投入 21—35 h。** 这是替代方法的可行性检查，**不是 R1**，不因任务勾选完毕自动认定 R0 通过。

## 1. 这一波只回答一个问题

在相同执行接口、允许延迟转移规律、不确定性覆盖、备份能力和每拍计算预算下，能否提出一个相对**可靠逐拍可达集方法**及已有事件触发/约束筛选方法有明确差异、并能保留覆盖且带来实际收益的计算调度或约束筛选步骤？

上一波已给出的边界：旧执行历史剪枝 `P` 在允许时变延迟时漏覆盖，停止作为论文创新点；端点 2 支和 7 个恒定延迟分支不能充当任意时变延迟的可靠基线。位置命令模型在独立验证中的 10 步最大误差 **0.1904 m**，超过设计裕量 **0.15 m**；现有模型级证书不能外推为 SITL/实物安全保证。CE1/CE3 的“不可认证”不等于 `P` 有优势，也不等于现实问题已被解决。

**本轮不做**旧 `P` 继续开发、CE1/CE3 反复调参、大规模 RL 训练、确认性实验或先行扩展 SITL。`two/16` §4 提议的“点延迟备份改为分支＋扫掠净空”已在 [`certificate_v2.py`](../../../../experiments/paper_v3/fair_compare/certificate_v2.py) 实现，不再列为新任务。

## 2. 任务顺序、交付物与判据

### T1：最近邻核查与具体命题（第 1—2 天，6—9 h）

- [ ] 精读最接近的**事件触发安全过滤、约束筛选/压缩、可达集快速外包或证书复用**原文。记录至少 3 个真正接近的算法，不以摘要或名称替代算法与假设检查。沿用 [`two/08_nearest_neighbor_table_v2.md`](../two/08_nearest_neighbor_table_v2.md) 中已核实的来源，新增来源保留版本、页码/公式及访问日期。
- [ ] 写一页差异表：各方法允许的延迟转移规律、状态/历史信息、覆盖或递归可行性前提、备份及超时语义、主要计算步骤。明确哪些已经解决拟议问题。
- [ ] 只选**一个**可证伪候选步骤，例如安全约束筛选、计算调度或上次证书复用；写出输入、输出、保守性条件、一个能让它失败的例子，以及相对最近邻的新内容。若第 2 天仍说不清差异，立即进入 §4 的改题准备，不为填满 5 天强行实现。

**交付**：`three/01_最近邻与命题.md`。**通过**：能指出具体算法步骤及最近邻未覆盖的条件/性质；“代码更快”“比旧 DQN 好”不算方法差异。

### T2：冻结同约束评估协议（第 2—3 天，3—5 h）

- [ ] 选定一个主转移规律并写清物理依据；**逐拍任意延迟**若仍在任务范围内，标准安全基线采用 [`two/15`](../two/15_time_varying_coverage.md) 的逐拍可达集传播。固定延迟与单次跳变另列，不把它们的零违例外推到任意切换。
- [ ] 统一模型、命令限制、方向误差、可见信息、候选集、共同备份、计算机/运行环境与时限。控制侧不读真值；各方法对同一组预先登记的场景运行。
- [ ] 预先固定指标：逐时域覆盖、物理碰撞与裕量违例、假安全证书、通行/停滞、证书不可用、备份接管、每拍工作量及 p50/p95/最大耗时、超时次数。记录独立运行身份、失败与缺失；比较**相同安全要求下**的成本和通行，不用不可靠的端点 2 支制造效率优势。
- [ ] 在看 T3 结果前写下**最小有意义收益**及理由：选择“p95 计算耗时降低至少 20%”或“同一每拍时限下通行率提高至少 10 个百分点”作为主判据，并固定重复计时次数；结果不达标时不得事后换主指标。
- [ ] 备份与候选执行按 [`two/14`](../two/14_offline_protocol_and_comparison.md) 的逐拍协议；对“证书只核对首个命令”另作限定，不能把首元素相同写成完整未来轨迹或一般安全保证。旧位置模型结果标 `model-level`；本轮不声明统计安全边界。

**交付**：`three/02_对照协议.md`，含固定的场景/参数/指标清单。**通过**：另一人可按清单独立复算；至少有一个安全应通过、一个必须拒绝、一个时变延迟切换、一个求解超时/备份接管样例。

### T3：最小原型与否决测试（第 3—4 天，8—12 h；仅在 T1 通过后）

- [ ] 只实现 T1 选出的那一步及必要适配；保留可靠全量方法和最接近的已发表简化法为对照。原型、对照及评分分开保存；不读取验证样例的真实延迟来筛选分支。
- [ ] 首先跑反例与超时样例。任何缩小范围、跳过约束或复用证书，都须有可检查的包含/有效性条件；一旦漏覆盖或给出假安全证书，直接记失败，不靠事后调大裕量遮盖。
- [ ] 在同一实现路径下记录确定性的工作量计数，并重复墙钟计时；记录精度、机器负载与尾部耗时。把观察到的收益拆为算法步骤造成的变化和实现差异。若没有收益，保留负结果。

**交付**：`three/03_最小探针.md`、版本化代码与逐 trial 数据。**通过**：结果可复算；至少能清楚判断候选的覆盖、计算与通行相对强基线的关系。不能以一个合成场景的零违例宣称一般安全。

### T4：第 5 天研究决定（3—5 h）

- [ ] 对照 T1 的原文和 T2 的预定判据，写明“继续新候选 / 停止算法主线并改题 / 证据不足需一个最小补充实验”三选一；逐条链接原始数据，不以目录齐全、退出码 0 或布尔汇总自动通过。
- [ ] **继续新候选**只在同时满足以下条件时成立：有可复述的最近邻差异和可检查性质；全部预定反例中未漏覆盖或虚报安全；在同等安全约束与预算下达到 T2 预先登记的主收益阈值且重复运行方向一致。此时再列下一轮的模型误差校准、强基线和针对性 SITL 工作，不自动启用原 R1。
- [ ] **未满足则止损**：停止安全过滤算法主线，按 §4 给“闭环失效边界仿真测试方法”做选题检索和与导师讨论，不把既有平台或更多训练轮次包装成新方法。若只是某一项证据缺失，补充实验必须说明它能翻转哪项判断，追加上限不超过 1 周，且不重做已完成的备份修正。

**交付**：`three/04_研究决定.md`，附一页导师讨论材料。导师的真实回复、日期和要点单独记录；未收到回复不阻塞可逆的技术分析，也不假记为同意。

## 4. 若 T1/T4 否决算法候选：改题准备

下一题只先做**选题可行性检查**，不是自动投稿路线。候选问题为“同等仿真预算下，如何更有效地找到闭环控制的失效边界并可靠估计其范围”。先检索失效边界搜索、反例生成、主动测试和重要性采样最近邻；提出与随机/分层采样的公平基线、独立确认样本及预算口径。定向搜索发现的失败样本比例**不能**直接当作自然碰撞概率。与导师讨论题目、资源和目标期刊要求后，再另发后续执行任务。
