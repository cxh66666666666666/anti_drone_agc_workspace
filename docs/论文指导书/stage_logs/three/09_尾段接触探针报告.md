## 一、探针如何落实 §4.1 的要求

| §4.1 要求 | 实现 | 证据位置 |
|---|---|---|
| 固定共同观察上限、终止后安全动作、停稳判据、尾段窗口 | `--tail-seconds`（默认 8 s）、`--postterm-action {hold,continue}`（hold=设定点回冻结到终止拍实测位置）、`--stop-speed`/`--stable-window` | `experiments/paper_v3/tail_contact_probe/tail_contact_probe.py` |
| 命令发布 / 位姿 / 速度 / **Gazebo 接触** / **几何净空** 同一时间基记录 | 每行同时写 `t_sim`(/clock)、`t_mono`、`t_wall`；`sources` 列标明该拍哪些链路新鲜；接触事件另写 `contact.csv` | `results/*/trace.csv`、`contact.csv`、`publish_log.csv`、`clock.csv` |
| 观察器只读物理真值；控制器不得读评分真值 | 探针控制侧只用 `/mavros/*` 与已发布命令；真值来自 `/gazebo/model_states`，仅用于记录与净空复算 | `meta.json: observer_reads_truth_only=true` |
| 失联 / 接触信号缺失 / 复位失败分别标记，不当作无碰撞 | `drop_rows`（该拍无任何链路）、`contact_signal_missing`（整 run 无接触话题消息）、`reset_ok/reset_failure_reason` | `meta.json`、`recompute.py` |
| 先空场景与可控接触核验事件源 | `--mode empty` / `--mode contact` | §三.1、§三.2 |
| 再在少量真实回合检查链路 | `episode_tail_probe.py`：**不改 gazebo_env.py**，靠控制 reset 时机在 `done` 后原地观察 | §三.5 |

**关键实现选择**：探针**不修改** `gazebo_env.py`。它自行掌握 `env.reset()` 的调用时机，因此某回合 `done` 之后、下一次 `reset` 之前，可以原地继续观察 `tail_seconds`——这段就是「终止后物理尾段」。

## 二、接触事件源（本批唯一新增物理测量）

`make_contact_model.py` 从 PX4 原版读入并在 `</model>` 前**注入**一段 bumper 链，派生到探针目录；原文件只读：

| 文件 | SHA-256 |
|---|---|
| 源 `.../PX4_Firmware/Tools/sitl_gazebo/models/iris_3d_lidar/iris_3d_lidar.sdf` | `7cd02558661021cf6bb6bd55637b84fadfd022568ee94a3d648b3cf4f398bbd3` |
| 派生 `models/iris_3d_lidar_contact/iris_3d_lidar_contact.sdf` | `92c16d05214bbbb70f9b10532003fe85aaf8ce1b826685bca4922f1648c97b28` |

注入内容与理由：

- `bumper_link`：box **0.70 × 0.70 × 0.11 m**，与 `geometry_metrics.DEFAULT_DRONE_HALF_EXTENTS = (0.35, 0.35, 0.06)` 的包络一致，便于「几何代理 vs 物理接触」同尺度对照；
- 抬高 0.055 m，使底面不低于机体底面，减少停机时的伪地面接触；
- contact 传感器 + `libgazebo_ros_bumper`，发布 `gazebo_msgs/ContactsState` 到 **`/drone_contact`**。
- 插件 `libgazebo_ros_bumper.so` 在 workspace `devel/lib`，**不在默认 Gazebo 插件路径**，故探针显式把 `devel/lib` 前置到 `GAZEBO_PLUGIN_PATH`（见 `meta.json: gazebo_plugin_path`）。
- `start_sim.sh` 仅增加一个向后兼容的 `SITL_SDF` 环境变量（默认行为不变），用于把派生模型接到 `sdf:=`。

**接触信号语义（决定「信号缺失」如何判定）**：该插件在每次传感器更新时都发布，**`states` 为空即无接触**；因此只有「整个 run 一条消息都没有」才判 `contact_signal_missing`。地面接触按名字过滤（`ground_plane`/`asphalt_plane`），另记 `kind=ground`，不计入碰撞。

## 三、实测结果

所有 run 均在无头模式运行；`drop_rows=0`、`contact_signal_missing=false`、`use_sim_time=true`、Gazebo 真值模型名 `iris`。完整数据在 `experiments/paper_v3/tail_contact_probe/results/`，可由 `recompute.py` 从日志重算。

### 3.1 空场景（`empty_01`）：核验四条链路

起飞→悬停→前移 1 m→悬停 6 s。983 行 trace，四条链路（MAVROS 位姿/速度 + Gazebo 真值）逐拍齐全；**物体接触 0 次**；接触话题 2812 条消息（信号存在）；起飞前 5 条 `asphalt_plane` 地面接触已被正确归为 `ground`。→ 事件源与时间基核验通过。

### 3.2 可控接触（`contact_hit`）：接触事件确实按物理发生

在机体前方 2 m 生成 0.3×0.3×3.0 静态障碍，以 0.6 m/s 逼近；终止时刻判为「真值净空首次 ≤ 0」；终止后 `continue`（继续原命令）以**保证**撞上。

- 终止 `t_sim=27.204`；**首次物体接触 27.188**（比几何穿越早 **16 ms**）；
- 物体接触消息 **435 条**；尾段最大外扩 0.179 m；尾段真值最小净空 −0.059 m。

### 3.3 截断后尾段碰撞：旧口径会漏掉（`tail_a`、`tail_b`，2/2 复现）

以 1.0 m/s 逼近，**在真值净空 0.25 m（仍为正）时判为「任务终止」**（模拟过滤器/超时类提前截断），随后执行 `hold`（安全动作=冻结在终止拍位置）并观察 8 s。两次独立运行的参数与结果：

| run | 终止时刻 | 终止时净空 | 终止后最大外扩 | 首次物体接触 | 接触消息 | 尾段真值最小净空 |
|---|---|---|---|---|---|---|
| `tail_a` | 25.860 | **+0.25 m** | 0.405 m | 26.084（尾段内） | 70 | −0.071 m |
| `tail_b` | 25.464 | **+0.25 m** | 0.303 m | 25.684（尾段内） | 67 | −0.073 m |

**读法**：按「截断即结算」的旧口径，这两次都在净空 0.25 m 处结束，属于**未碰撞**；但机体带着约 1.0 m/s 的残余速度继续外扩 0.3—0.4 m，**在尾段发生了真实接触**（独立 Gazebo 接触事件证实）。即：**截断口径会把已发生的物理碰撞记为未碰撞**，本批 2/2 复现。两次的尾段最大俯仰约 14°。

### 3.4 反向失配：估计位姿口径会「虚报」碰撞（`contact_tail`）

同参数但终止阈值放到 **0.5 m**、终止后 `hold`。终止 `t_sim=26.028`（净空 +0.50 m），尾段外扩 **0.484 m**。

- **独立接触事件：0 次**（尾段真值最小净空 +0.0085 m，始终未相交）；
- 但**基于 MAVROS 估计位姿**的净空一度到 **−0.0164 m**。仓库 [`gazebo_env.py`](../../../../src/rl_obstacle_avoidance/scripts/gazebo_env.py#L1878-L1891) 的判据用估计位姿，**会把这拍记为碰撞**。

→ 与 3.3 相反方向的失配：**估计位姿口径可虚报一次物理上并未发生的碰撞**。仅 1 个样本，不作发生率结论。

### 3.5 真实回合（`episode_shield`、`episode_dqn_a1`）：链路打通，但终止原因未覆盖到目标项

用真实场景 `s3v1-04113e4f41`（含竖柱与注入的传感器失效窗口）跑既有 `GazeboEnv` 闭环，`done` 后原地观察 6 s：

| run | 策略 / 过滤器 | 回合数 | 终止原因 | 尾段观察 | 尾段接触 |
|---|---|---|---|---|---|
| `episode_shield` | nominal + A1（空集严格终止） | 2 | `timeout`×2 | 6.02 s×2 | 0 |
| `episode_dqn_a1` | 冻结 DQN(v5b) + A1（空集严格终止） | 3 | `timeout`×3 | 6.01 s×2 + 6.02 s | 0 |

链路（真实场景 + 真实终止 + 尾段续记 + 接触监测）打通：5 个真实回合尾段真值最大速度与最大位移分别约 0.49 m/s 与 2.24 m（位移是否沿名义参考，本批未单独核验）。尾段均无物体接触。
**但本批未产出 `shield_infeasible` / `perception_timeout` / `sensor_invalid`**：A1 严格终止档下安全集始终含逃逸动作（日志 `allowed=[5]`），未触发空集终止；传感器失效窗口按 `trajectory_phase_s` 判定，本配置下 `features_fresh` 始终为 1。**这是本批的真实缺口，不作为已完成项。**

### 3.6 两种净空口径的系统差

悬停段以同一时刻的 Gazebo 真值减 MAVROS 估计：`dz = +0.210 ± 0.018 m`、`dx = −0.031 ± 0.025 m`、`dy = +0.012 ± 0.013 m`（n=300）。相应地，同拍两种净空口径之差在 0.03—0.13 m 量级（各 run 的极值可达 ±0.07 m）——**与碰撞裕量同量级**。

## 五、结论与证据边界

**能下的结论（限本批）**

1. 终止后物理尾段**可被稳定记录**：统一时间基的命令/位姿/速度/接触/净空链路工作，`drop_rows=0`、接触信号存在。
2. **「截断即结算」会漏掉尾段碰撞**：在净空 0.25 m 处截断、残余速度约 1.0 m/s 时，尾段外扩 0.30—0.40 m 并发生真实接触，**2/2 复现**。
3. **两口径都可能不一致，且方向不同**：真值/估计净空在同拍可差 ±0.07 m 量级（估计位姿在 z 上系统性低约 0.21 m）；至少 1 个样本里「估计位姿口径判碰撞、独立接触事件判无接触」。
4. 接触事件源可信：空场景 0 物体接触；驱入障碍时可靠产生接触；终止前后接触时间与几何穿越时间相差约 16—20 ms。

**不能下的结论**

- 不能由本批推断**发生率或对算法排序的影响**：受控样例是单机型、单障碍、单速度档，`contact_tail` 仅 1 样本；真实回合仅 5 个且全为 `timeout`。
- 不能宣称「终止后必有碰撞」或「尾段碰撞普遍发生」：`contact_tail`（阈值 0.5 m）尾段并无接触，说明**是否发生依赖截断时的净空与速度**，本批只给「存在且可复现的一个方向」。
- 不能把几何代理与接触事件说成同一测量：二者在时间与符号上都出现过不一致，机理（机体俯仰出包络 / 估计位姿偏差 / 求解器接触容差）在本批**未做分离实验**。
- 不能外推到实飞或真实碰撞概率：全程 SITL；人为截断条件不代表任何真实故障分布。

## 六、尚缺与下一步（不进入 §4.3 前的门槛）

1. **真实终止原因未覆盖**：须产出 `shield_infeasible` / `perception_timeout` 回合（本批 A1 严格档未触发空集；失效窗口未激活），并核对这三类原因下的尾段差异。
