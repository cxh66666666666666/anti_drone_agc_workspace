### 5.3 不可达场景的接口审计（按任务状态判断）

不可达场景下 `ground_planner` 无可行路径，`/agc/ground/path` 依契约（≥1 Hz 且非空）**不发布**，故现场接口审计报 `频率 /agc/ground/path 0.00 Hz` 与 `样本 /agc/ground/path`（窗口内无消息）两项 FAIL，其余全部 PASS。这是「目标不可达」的**必然语义**，非缺陷。

核验脚本不为 fault 类别**整体**豁免，而是**按任务状态**条件豁免：仅当（1）非 path 项无 FAIL、（2）path 频率/样本项缺失、（3）该场景**全部回合**按预期正确失败（`final_state=5`、`reason=PLAN_UNREACHABLE`，即无可行路径且正确失败）三条同时成立时，path 项才豁免通过。任一条件不满足即判 FAIL——名义场景缺 path（异常无路径）、或失败原因非 `PLAN_UNREACHABLE`，都不得据此放行。名义/丢失场景 path 项全通过（名义实测 `频率 /agc/ground/path 1.99 Hz`）。

判定实现见 `scripts/verify_m6_scenarios.py`：`audit_path_failures()` 从各批次目录的 `audit_interfaces_cycle*.json` 拆分 path/非 path FAIL，`E2` 项按上述三条据任务状态结算。

## 八、未决事项

1. **单次启动内多次 attempt 的复位独立性问题（重要发现）**：`ground_drive_adapter` 在任务**非运行期**仍每拍把积分位姿写回 `agc_car`，会覆盖 `scenario_reset` 写入的 `car_start`；而它在复位换序时重同步的是「Gazebo 实际位姿」，此时可能已被自己的写回覆盖，导致**同一栈内后续 attempt 并非从场景初值开始**。M1 权威批次（`_m1_batch_20260927T051409`）亦可见此现象（同循环 attempt2 车起点为 attempt1 终点 `(6.09,2.54)`，非 `(-4,-3)`）。本轮 M6 以**每回合一个全新栈**规避，并逐回合核验起点独立（A4）。**已修复**：在 `ground_drive_adapter` 增加「任务非运行期不写位姿」的门控（与契约 §4「运行期唯一写入者」一致），使单栈内多 attempt 的复位也成立；该改动会影响 M1/M5 的复位/残留证据，已在其框架内重新验收。

**已于 2026-10-05 修复**：`ground_drive_adapter` 增加 `/agc/task/state` 运行期门控（任务非运行期不写 `agc_car` 位姿，`drive_log.jsonl` 增 `task_running` 字段）。非无头复核批次 `experiments/agc_runs/_m1_batch_20261005T090527`（`--cycles 1 --repeat 3`）中 3 个 attempt 均从场景初值 `car_start (-4,-3)` 起算、终态 `TRACKING_SUCCESS`、`any_leftover=false`；M5 回归见 [M5 第九节](../M5/M5_控制权交接验收_v1.md)。故本轮以“每回合一个全新栈”规避的做法不再是必需，但既有 8 回合成套证据保持不变。
2. **安全接近点与规划栅格保护距离边界一致性**（M3/M5 未决）：本轮把「目标贴近障碍」构造为**不可达**场景（`PLAN_UNREACHABLE`），未修改规划/目标格可行化。若要使其变为**可达**，需在 `safeApproachPoint` 采用 `≥ protection + res/√2` 的回退余量或对目标格做可行化处理。**已由 N3 解决（2026-10-06）**：采用「目标格可行化」方案（`ground_planner` 在 `planner.goal_adjust_max_m` 半径内就近取可行格，不降保护阈值）。新批次 `_n3_reg_m6unreach_20261006T073404` 中本场景（`scenario_unreachable.yaml`，hash `02f1139d…` 不变）在当前代码下由 `MISSION_FAILED/PLAN_UNREACHABLE` 转为 `TRACKING_SUCCESS`（`goal_adjusted=39`、最小净空 1.113 m ≥0.80）——**即本文所谓「不可达」实为「可达但目标格落点错误」**。本文冻结报告与哈希不改（记录旧代码状态）；「确实无路」现有独立封闭场景 `scenario_truly_blocked.yaml` 承载。详见 [N3.md](../../阶段2/N3.md)。
3. **不可达场景的接口审计**：该场景 `/agc/ground/path` 依设计不发布，现场审计的 path 频率/样本项必然 FAIL。**已定义（N0）**：不再对 fault 类别整体豁免，改为**按任务状态**条件豁免——仅当非 path 项无 FAIL、path 频率/样本项缺失、且该场景全部回合正确失败为 `MISSION_FAILED/PLAN_UNREACHABLE`（无可行路径且正确失败）时豁免；异常无路径（名义场景缺 path、或失败原因非 `PLAN_UNREACHABLE`）仍判 FAIL。实现见 §5.3 与 `verify_m6_scenarios.py`。
4. **场景数量与随机化**：本轮每类 2 个固定回合（共 8），未做随机化/参数扫描；M7 可在固定训练/验证/测试集上扩展样本量。
