## 一、任务口径

M2 要求：把空中平台、地面车、障碍物和目标放进同一任务世界，统一 `/clock`、坐标系、模型命名和日志时间戳；确认地图接口。交付物三项：同一 run 中可同时读取空地与目标位姿；已验证坐标变换和时间戳；一个启动入口和一个干净退出入口。

**实现基线说明**：共同世界（`agc_world`）、全局 `/use_sim_time=true`、`world`/`air_local`/`drone/base_link`/`car/base_link` TF、模型命名与适配器日志已在 M0 改造中落地并被 M0/M1 验收间接覆盖。本轮 M2 补齐**专用验收证据**，并按契约 §5.2 完成**地面车保护距离标定**。

非目标（按用户决定）：不推进 M3–M9；不做阶段 B 拦截、真实融合与实物；M1 遗留项（终态→同码终态 run 边界、复位后 odom 瞬态根因）不在本轮。

## 四、地面车保护距离标定

净空度量：**车中心到障碍 OBB 表面的有符号距离**（`agc::pointObbClearance`，在障碍内部为负）。

| 参数 | 值 | 推导依据 |
| --- | --- | --- |
| `car_radius_m` | 0.30 m | 车体 OBB `0.44 × 0.34 × 0.16 m`（`models/agc_car/agc_car.sdf`）二维外接圆半径 `sqrt(0.22²+0.17²)=0.2784 m`，取 0.30（含 0.02 m 裕度）。**接触/几何相交判据**：`clearance ≤ car_radius_m` |
| `emergency_m` | 0.35 m | `car_radius 0.30 + 单控制步位移(max_linear_speed 1.0 / drive_hz 20 = 0.05)`；触发 `EMERGENCY_TRIGGER`（事件，不改结局） |
| `protection_m` | 0.80 m | `car_radius 0.278 + 地图量化误差(resolution/√2 = 0.5/√2 ≈ 0.354) + 单控制步 0.05 + 裕度 0.10`；触发 `CLEARANCE_VIOLATION`（事件，不改结局），同时是成功条件 3 与规划膨胀下界 |

阈值顺序：`接触(car_radius 0.30) ≤ emergency(0.35) < protection(0.80)`。

### 4.1 与契约口径的对齐（修正项）

- **移除 `clearance.collision_m`**：契约 §5.2 只定义「碰撞/几何相交」与两类保护带事件（`CLEARANCE_VIOLATION`、`EMERGENCY_TRIGGER`），无 `collision_m`。此前 `GROUND_COLLISION = (clearance ≤ collision_m=0.50)` 会在车面尚有约 0.20 m 间隙时就把「接近」记成「碰撞」。现改为 `GROUND_COLLISION` 仅由接触/几何相交触发（`clearance ≤ car_radius_m`）。
- **净空阈值单一来源**：删除 `scenario_flat.yaml` 中重复且从未被任何节点消费的 `thresholds.clearance_*`（死配置），净空阈值以 `agc_params.yaml` 的 `clearance` 段为唯一来源；该段哈希已写入 run `meta.json` 的 `agc_params_hash`。
- 标定值与 run `meta.json` 逐项核对一致：`params.clearance = {car_radius_m: 0.30, emergency_m: 0.35, protection_m: 0.80}`，不含 `collision_m`。

## 六、未决事项

1. **阈值随场景文件锁定留待 M6**：契约 §5.2 期望「每个场景在 run 前锁定具体阈值与配置哈希」。本轮净空阈值以 `agc_params.yaml` 为唯一来源（其哈希已入 run 日志），多场景的 per-scenario 阈值锁定待 M6 增加场景时另行设计（现有 `thresholds` 段的净空项已清空，其余场景阈值仍为未消费字段）。
2. **保护带事件未被强制触发**：规划膨胀使执行轨迹净空 ≥ `protection_m`，故 `CLEARANCE_VIOLATION`/`EMERGENCY_TRIGGER` 本批仍以代码路径核查为准，未构造接触场景；两类事件不改变任务结局。
3. **空中 odom 与 Gazebo 差值 0.1205 m** 出现在起飞后悬停窗口（`gazebo z=2.300` vs `odom z=2.188`），在 0.20 m 容差内但余量不大；该值为非稳态采样，标定残差本身仅 0.0010–0.0038 m。若后续要收紧容差，需在严格悬停稳定点取样。
4. **批跑目录命名**：脚本仍以 `_m1_batch_<ts>` 前缀生成，本轮重命名为 `_m2_batch_<ts>`；未改脚本以免影响 M1 既有证据路径。
5. **M1 遗留项**：终态→同码终态的 run 边界、复位后 odom 瞬态根因、`air_handover.json` 归属、起飞窗口 `AUTO.LAND` 抖动，均已于 2026-09-27 另行修复（不在本轮 M2 范围内），见 [M1_单体验收_v1.md](../M1/M1_单体验收_v1.md) 第九节。
