# M3 空地最小闭环（空中信息→地面规划→执行）验收 v1

> 2026-10-03；依据 [下一阶段任务清单.md](../../项目指导书/下一阶段任务清单.md) 的 M3（P1）与 [M0_接口契约_v1.1.md](../M0/M0_接口契约_v1.1.md) 第三、六、七节。证据根目录：`experiments/agc_runs/`。本版只覆盖 M3：**真值适配器路径下「空中目标改变⇒地面规划与动作随之改变」的因果闭环 + 无信息安全停车**，不含 M4 真实感知融合、M5 控制权、M6 多场景、M8 实物；不宣称拦截完成。

## 一、任务口径

M3 要求：打通空中信息到地面规划的最小闭环（规划算法 + 消息桥、调用、执行与反馈）；先用可控仿真真值适配器验证接口，随后接入真实空中感知输出（后者属 M4）。完成时交付的可核查证据是：**改变空中观测/目标后，地面规划路径随之更新并驱动车运动；记录输入、规划结果、执行轨迹和重规划原因。**

**实现基线说明**：M0 已落地完整链路 `gt_adapter → /agc/targets → task_manager(/agc/ground/goal) → ground_planner(/agc/ground/path) → ground_commander(/agc/ground/cmd_vel) → ground_drive_adapter(写车体位姿)`，并在**静态目标**下验证过车确实运动（M1）。本轮 M3 补齐的是**因果闭环的专用触发与证据**：核查全仓 157 个 `planner_log.jsonl`，`trigger="displacement"`（目标位移 >1 m 触发重规划）出现次数为 **0**，说明「目标改变⇒地面规划随之更新」此前从未被实际触发。

非目标（按 Spec 定稿）：不推进 M4–M9；不改动任何实时链路节点、M0 已冻结话题/消息、launch、`scenario_flat.yaml` 与 `start_agc_collab.sh`。

### 3.2 输入→规划（空中目标改变 ⇒ goal/path 更新）

- 处理 run：目标地面位置变化 2.796 m；`/agc/ground/goal` 变化 2.796 m；goal 与目标地面投影中位距离 0.043 m、最大 0.125 m——**goal 逐拍跟随目标**。
- 重规划原因落盘：`planner_log.jsonl` 处理组 45 行全部含 `trigger/goal/car_pose/map_version_hash/plan_time_ms/n_waypoints/success/failure_reason`；其中 `trigger="displacement"` **28 次**、`period` 15 次、`first` 1 次。
- 对照 run：目标与 goal 变化均为 0.000 m，`trigger` 仅 `first/period/invalid`，`displacement=0`——**不改变空中输入就不产生目标驱动的重规划**，与处理组形成对照。

### 3.3 规划→执行（更新后的规划驱动车运动）

- 处理 run：车实际位移 13.712 m；`GROUND_APPROACH` 窗 [64.26, 79.90] 内 283/312 个 `/agc/ground/cmd_vel` 样本 `linear.x>0.05`（峰值 1.000 m/s）；相邻位移朝向当前 goal 的平均余弦 0.549 > 0。
- 执行轨迹来源：`/agc/ground/odom`（Gazebo 实际车体位姿，`ground_odom_adapter`），非驱动器内部积分状态。

## 四、可达性核查发现的未决问题（本轮记录，未改实时节点）

初版处理组航段沿用场景默认 `y=2.5`（目标 `(6.5,2.5)<->(3.5,2.5)`）。该航段地面投影经过 `pole_2` 附近时最小净空约 **0.75 m < `protection_m` 0.80**，触发两个连锁行为：

1. `task_manager.safeApproachPoint` 沿「车→目标」方向回退，使 `goal` 落在刚好满足 `clearance ≥ 0.80` 的**边界点**；
2. `ground_planner` 的膨胀栅格把「cell 中心净空 <0.80」的格判为阻塞，边界点所在栅格常被判阻塞 → `astar_no_path` 连续失败 → `/agc/planner/unreachable=true`；`ground_commander` 因该标志零速，`task_manager` 在 `GROUND_APPROACH` 内直接结算 `PLAN_UNREACHABLE`。

证据（反例 run，均 `MISSION_FAILED/PLAN_UNREACHABLE`）：`20261003T015437_096a30`、`20261003T015601_f88194`（批 `_m3_batch_20261003T015432_reachability_fail`；planner 日志中 `infeasible` 26–28 次）。

**性质**：属「安全接近点（精确几何）与规划栅格（量化膨胀）在保护距离边界不一致」，非空地接口问题。**处置**：按契约 §5.1「目标运动场景须先做可达性检查」，本轮把航段改为净空充裕的 `(6.5,2.5)->(8.5,4.5)`（最小净空 ≈2.04 m），**不改动实时节点**；该边界一致性建议在规划/控制阶段（M5）另行处理。

## 五、结果口径与措辞核对

- 阶段 A 终态为 `TRACKING_SUCCESS`（含义：地面车在目标地面投影附近持续跟踪），**不得表述为拦截完成**；全部 run 未出现 `INTERCEPT_CONFIRMED`，未发生 `GROUND_COLLISION`。
- 目标高度 2.0 m，平面距离 ≤3.0 m 不代表可接触；`TRACKING_SUCCESS` 与拦截是两回事。
- 目标/`goal` 跟随关系按**任务活动窗口**（任务状态非 `IDLE` 的首/末时刻）评估，并排除每次 `/agc/scenario/reset` 后 2.0 s：复位按设计把目标写回 `target_start`，其瞬移与目标运动无关。本版处理 run 的任务窗为 [63.272, 80.400]，复位排除 3 处。

## 七、未决事项

- **安全接近点与规划栅格的保护距离边界一致性**（第四节）：建议在规划/控制阶段修正（如把安全接近点净空提高到 `≥ protection + res/√2`，或让规划对目标格做可行化处理），使「目标贴近障碍」的移动场景也可直接评估。
- **`/agc/planner/unreachable` 的跨阶段残留**：规划在任务开始前的 `IDLE` 段即在重规划，一旦该标志被置位，进入 `GROUND_APPROACH` 后会立即结算 `PLAN_UNREACHABLE`；是否应在 `start` 时清零该标志，留待 M5 控制权/状态机阶段决定。
- 本轮只改变**目标**输入；「改变障碍/地图输入⇒规划更新」属 M2/M4/M6 范围。
