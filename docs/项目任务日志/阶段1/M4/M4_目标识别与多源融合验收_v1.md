# M4 目标识别与多源融合验收 v1

> 2026-10-03；依据 [下一阶段任务清单.md](../../项目指导书/下一阶段任务清单.md) 的 M4（P1）与 [M0_接口契约_v1.2.md](../M0/M0_接口契约_v1.2.md) 第八、九节。证据根目录：`experiments/agc_runs/`。本版只覆盖 M4：**多源空中观测→融合输出被 M3 规划链路消费；延迟/丢失/冲突注入时行为可解释；confidence 可标定**。不推进 M5 控制权、M6 多场景、M8 实物；不宣称拦截完成。

## 一、任务口径与诚实说明

M4 要求：接入目标识别与多源融合，负责接入、超时/失联处理与端到端日志；交付「目标/障碍消息含来源、坐标系、时间戳、置信度；融合结果可被 M3 消费；注入延迟、丢失和冲突观测时有可解释行为」。

**诚实说明**：本阶段的「目标识别」是**由 Gazebo 真值派生的感知仿真**（`air_perception` 对真值加噪/延迟/丢包/离群），**不是真实视觉/雷达识别**；不据此宣称完成真实目标探测。真实感知接入属后续实物品类工作。

## 三、实现（实时链路 C++）

- **`air_perception`（新）**：读 `/gazebo/model_states` 真值，按 `perception_sensors.yaml` 的 2 个通道（`air_eo_front` σ_xy=0.10、`air_ir_top` σ_xy=0.20）独立加噪/延迟/丢包/离群偏置，发 `/agc/air/obs`；观测 `header.stamp`=原始观测时刻，延迟只推迟发布（故 age 随延迟增长）。confidence 由 Rayleigh 径向覆盖解析：`conf=1-exp(-tol²/(2σ²))`。故障在线可调 `/agc/perception/fault/<sensor>/{enabled,drop_prob,latency_s,outlier_bias_m}`；落 `perception_log.jsonl`。
- **`air_fusion`（新）**：订阅 `/agc/air/obs`，对每通道做新鲜度（age ≤0.35 s）、置信度（≥0.5）、空间一致性（与参考估计距离 >1.5 m 判离群）门控；仅对 inlier 逆方差加权，协方差以 `correlated_pad_m` 设下界（同源相关，不按 1/N 缩小、不跨源取最大）；目标→`/agc/targets`（`source=air_fusion`，`header.stamp`=最新真实观测时刻），障碍→`/agc/obstacles`（按 `obstacle_id` 关联 inlier，并集+保守外扩）。无有效观测发空数组；落 `fusion_log.jsonl`（输入/门控/离群/输出/拒收原因）。
- **`gt_adapter`**：仅当 `target/source=gt_adapter` 时 advertise `/agc/targets`（防双发布者）。
- **`map_adapter`/`ground_planner`**：`obstacles/source=air_fusion` 时改用 `/agc/obstacles` 融合障碍（地图几何仍取场景 map 段；map_adapter 带内容哈希门限防重规划风暴）。`source=scenario` 时路径与 v1.1 完全一致（构造性等价）。
- **`task_manager` 不改安全判据**：净空/碰撞/紧急判据统计始终用场景真值几何（**感知驱动规划、真值裁判安全**）。
- **`agc_run_logger`**：`meta` 增 `target_source`/`obstacle_source`、`CONTRACT_DOC`→v1.2、增 `/agc/air/obs` 与 `/agc/obstacles` 记录与进程清单。
- **编排**：`agc_collab.launch` 增 `target_source`/`obstacle_source`（launch 单一设置 source 参数，`gt_adapter` 与 `air_perception+air_fusion` 条件包含）；`start_agc_collab.sh` 增 `--target-source/--obstacle-source/--inject/--inject-sensor/--inject-value/--inject-delay/--batch-prefix`。
- **离线工具（Python）**：`m4_inject.py`（按 rosparam 在线注入并落 `injections.jsonl`）、`verify_fusion.py`（离线核验）。`audit_interfaces.py` 按 source 组织期望接口表并支持 `--fault-mode`。

### 5.1 观测字段与坐标系（契约 §8.1）

`/agc/air/obs` 每条目标/障碍观测含非空 `sensor_id`、`header.frame_id=world`、`header.stamp>0`、`0≤confidence≤1`、单调 `obs_seq`；融合输出 `TargetTrack`/`ObstacleTrack` 均带 `source`/`frame_id`/`stamp`/`confidence`。

### 5.2 融合结果可被 M3 消费（契约 §8.2）

`air_fusion` 源下 `/agc/ground/goal` 逐拍跟随融合目标（中位 0.109–0.113 m），状态机正常结算（normal/latency/conflict/obstacle 均 `TRACKING_SUCCESS`，state=4），说明 M3 因果闭环在融合源下仍然成立。`/agc/targets` 的 `header.stamp`=最新真实观测时刻，无新观测即发空数组（丢失组详见 5.4）。

### 5.3 confidence 标定（契约 §8.3）

定义 `confidence` = 位置误差 ≤ `calibration.confidence_tolerance_m`（0.25 m）的经验概率；由噪声模型解析给出，并用 run 内观测与真值计算经验覆盖核验：

| 通道 | 声明 confidence | 各 run 经验覆盖 | 最大偏差 |
| --- | --- | --- | --- |
| `air_eo_front` | 0.956 | 0.954–0.965 | 0.009 |
| `air_ir_top` | 0.542 | 0.462–0.539 | 0.080 |

均 ≤ `coverage_tol_prob`（0.15）。真值基线 `gt_adapter` 保持 `confidence=1`；两类分数不直接比较。

### 5.4 延迟/丢失/冲突的可解释行为（契约 §8.4）

- **延迟**（`latency_s=0.8` > 融合门 0.35 s）：该通道观测年龄超限被判 `stale` 且不计入融合，输出由另一 inlier 通道支撑，任务不中断。
- **丢失**（全通道 `drop_prob=1.0`）：先获得目标并进入 `GROUND_APPROACH`，随后全通道无观测 → `/agc/targets` 转空 → 车在容忍窗内停稳（延迟 1.00 s）→ `TARGET_LOST`。
- **冲突**（`air_ir_top` 偏置 +3.0 m）：该通道与融合估计距离超 `gate_m`(1.5 m) 被判 `outlier` 并记录原因；融合跟随 inlier（`air_eo_front`），**未做跨源取最大**。

### 5.5 障碍接入规划与安全判据分工（契约 §8.5）

`obstacles/source=air_fusion` 时 `/agc/obstacles` 的融合障碍（`pole_1`/`pole_2`，保守外扩）被 `map_adapter` 建图与 `ground_planner` 膨胀消费；`task_manager` 净空/碰撞仍以场景真值几何结算（本轮无 `GROUND_COLLISION`/`CLEARANCE_VIOLATION`/`EMERGENCY_TRIGGER`）。`obstacles/source=scenario` 时 map 内容哈希与 M2 一致（`35b6d5c71a…`，构造性等价回归）。

### 5.6 单一启动 / 干净退出

六批均经唯一入口 `scripts/start_agc_collab.sh`。

**N0 复核（残留口径）**：融合 nominal 原始批次 `_m4_nominal_20261003T110811/batch.json` 实为 `any_leftover=true`，两条残留项为 `start_agc_colla`（编排脚本自身）与空 `comm`（其命令替换子 shell）；二者命令行含 `--target-source air_fusion`，被当时检测用的 `pgrep -f air_fusion` 误匹配为 `match=air_fusion`，但均为**编排层非任务节点进程**。旧脚本未排除自身/祖先与子 shell，属**误报而非真残留**。原始批次**保留不删**。

当前仓库脚本 `start_agc_collab.sh` 的 `proc_json` 已按自身/祖先 PID、`start_agc_colla` comm 与空 comm 排除，不再误报。以当前脚本重跑融合 nominal **复核批次** `_m4_nominal_recheck_20261005T123044`（`--gui --target-source air_fusion --obstacle-source scenario`）：`batch.json` `any_leftover=false`、`procs_after_exit=[]`、`audit_ok=true`、终态 `TRACKING_SUCCESS`、`verify_fusion` nominal PASS=7 FAIL=0。其余五批原始 `batch.json` 均为 `any_leftover=false`、退出后关键进程残留为空。

## 八、未决事项

1. **真实感知接入**：当前为真值派生感知仿真；视觉/雷达识别与融合属实物阶段，需另立接口与验收。
2. **相关噪声假设**：多通道同源、误差相关，融合协方差以 `correlated_pad_m` 设定下界为工程处理；若后续接入真正独立的传感器，应改为按独立模型融合并重标定 confidence。
3. **冲突门控的参考点**：参考估计优先用最近融合值（`reference_hold_s` 1.0 s），冷启动用最高置信通道；若注入通道恰为最高置信，冷启动下可能误拒正常通道——本组用低置信通道注入规避，建议 M5 增加稳健关联（如聚类/多数表决）。
4. **障碍源与规划栅格的边界一致性**：M3 记录的「安全接近点 vs 规划栅格保护距离边界」问题在融合障碍下依然存在（本组净空充裕未触发），建议 M5/M6 处理。
5. **注入批次命名**：权威延迟/丢失/冲突批以 `_m4_*2_*` 命名（第一版因注入时点晚于 `TRACKING_SUCCESS` 被取代），后续可统一命名。
