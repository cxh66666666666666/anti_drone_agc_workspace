# M0 接口契约 v1.1：空地协同仿真集成

> 2026-09-26；版本 `agc-m0-v1.1`。本文替代 v1.0（`agc-m0-v1.0`，该历史版本未随仓库保留；v1.0→v1.1 的主要差异见本节与第三、四节正文），作为 M1–M6 的实现与验收依据。本文先定义**抵近跟踪**闭环；“拦截完成”须等执行装置、捕获传感器与判据确定后另起版本，不能由车体或目标的任意接触推定。

## 一、任务边界

空中平台提供目标与环境信息；地面车据此规划、运动、避障并反馈。阶段 A（M3–M6）的成功仅称 `TRACKING_SUCCESS`，含义是地面车在目标地面投影附近持续跟踪。目标模型 `intruder_uav` 默认高度 2.0 m；现有低矮车体没有可验证的 2 m 高捕获装置，因此阶段 A **不产生** `INTERCEPT_CONFIRMED`，不宣称拦截完成。

阶段 B 启用前，团队须另行冻结：实际拦截机构及其几何覆盖、高度/速度可行域、目标与机构的指定接触或捕获信号、误触发排除方式、实物安全约束。仿真接触须核对**指定两碰撞体的接触对**，单个 contact sensor 的“任意接触”无效。真值适配器只是 M3 联调基线，接入 M4 感知融合前不得宣称已完成真实目标探测。

黄昊文负责协同任务与全局规划，秦可豪负责视觉目标识别与融合，陈鑫豪负责共同世界、接口、运动控制、局部避障、系统集成和日志。本文规定模块边界，不规定其他成员内部算法。

## 二、共同世界、坐标和时间

- 一个 `agc_world` / `gzserver` 包含本方无人机、地面车、目标和障碍；协同 run 不再启动独立 `ground_gazebo`。Gazebo 服务实际 namespace 由 launch 配置，协同层通过适配器访问。
- `world` 为 Gazebo ENU：+x 东、+y 北、+z 上，位置 m、速度 m/s、角度 rad。协同层带 Header 的位置、速度、地图、路径和状态消息使用 `header.frame_id=world`。地面 `goal` 是目标地面投影或规划出的安全接近点，`z=0`，不能直接把飞行目标的 2 m 高姿态当车的目标。
- 无人机 MAVROS 本地位姿经 `air_odom_adapter` 转换。每次启动/复位标定并记录 `T_world_air_local`、时间和残差；不能假定本地原点恒等于 spawn 点。EKF 重置、变换突变或 TF 失效使 odom 无效；当前 run 记基础设施失败，重新标定后开启新 run。
- TF 名称为 `world`、`air_local`、`drone/base_link`、`car/base_link`；两个 odom 的 `header.frame_id=world`、`child_frame_id` 对应机体，位置在 world 系，`twist` 按 ROS Odometry 约定表达在对应 child frame。适配器须把底层世界系速度旋转到机体系。地面 odom 从 Gazebo 实际车体状态生成，不从无 Header 的 `CarStatus` 位置字段或驱动器内部积分状态冒充反馈。
- 全局 `/use_sim_time=true`；任务消息 stamp、观测年龄和任务时限用 `/clock`。另用**单调墙钟**检查时钟停滞和进程失联，墙钟仅用于基础设施 watchdog 与日志，不混入任务时长。拒绝跨复位旧时间戳和未来时间戳；记录复位序号。

## 三、协同层接口

| 名称 | ROS1 类型 | 唯一发布者 | 更新与消费规则 |
| --- | --- | --- | --- |
| `/agc/air/odom` | `nav_msgs/Odometry` | `air_odom_adapter` | ≥20 Hz，年龄 ≤0.5 s；world 位姿、机体系 twist |
| `/agc/ground/odom` | `nav_msgs/Odometry` | `ground_odom_adapter` | ≥20 Hz，年龄 ≤0.5 s，实际车体反馈 |
| `/agc/targets` | `air_ground_core/TargetTrackArray` | `gt_adapter` **或** `air_fusion` | 10 Hz，无目标发空数组；只能有一个源 |
| `/agc/map` | `nav_msgs/OccupancyGrid` | `map_adapter` | ≥1 Hz 且变更即发；地图有原点、分辨率、尺寸；内容哈希作为地图版本写入规划日志，空图无效 |
| `/agc/ground/goal` | `geometry_msgs/PoseStamped` | `task_manager` | ≥5 Hz 且变化即发；年龄 ≤1 s；world，z=0 |
| `/agc/ground/path` | `nav_msgs/Path` | `ground_planner` | ≥1 Hz 且重规划即发；年龄 ≤2 s；world，非空 |
| `/agc/ground/cmd_vel` | `geometry_msgs/TwistStamped` | `ground_commander` | 20 Hz，含零速；年龄 ≤0.2 s；命令速度用车体系 |
| `/agc/task/state` | `air_ground_core/AgcTaskState` | `task_manager` | 2 Hz 且变化即发；年龄 ≤1.5 s |
| `/agc/task/start`、`/agc/task/abort` | `std_srvs/Trigger` | `task_manager` | start 仅在 IDLE 且门禁通过；abort 对任意非终态有效 |

`TwistStamped` 提供时间戳，底层适配器可以转换为插件/硬件所需的 `Twist`；其他节点不能绕过适配器发布执行命令。v1.0 的 `/agc/ground/reference_path` 在本版废弃，以 `/agc/ground/path` 为准。所有含 Header 的协同消息用仿真时钟；`TwistStamped.header.frame_id=car/base_link`，因为其速度是车体系，**不**强制写成 world。

新增 `air_ground_core/TargetTrack.msg`：

```text
std_msgs/Header header                 # 最后一次真实观测时刻；frame_id=world
string target_id                       # 阶段 A 为 intruder_uav
geometry_msgs/PoseWithCovariance pose
geometry_msgs/TwistWithCovariance twist
float32 confidence                     # 来源内已校准的观测质量
string source                          # gt_adapter / air_fusion
```

`TargetTrackArray.msg`：

```text
std_msgs/Header header                 # 数组发布时刻；frame_id=world
TargetTrack[] tracks                   # 未观测到有效目标时为空
```

重发旧 track **不能**刷新其观测时间。真值无噪声基线 `confidence=1`，协方差取已注明的数值精度；噪声场景须记录噪声模型与种子。融合模块接入前用验证数据标定 confidence 的意义（如位置误差处于预设容限内的经验概率）。未校准的真值分数与融合分数不得直接比较，也不得跨来源简单取最大值。阶段 A 仅一个目标源；来源切换须在 run 开始前固定。
`TargetTrack.pose` 与 `TargetTrack.twist` 均表达在 `header.frame_id=world`，与 Odometry 的 child-frame twist 约定不同；适配器须显式完成旋转。

`AgcTaskState.msg`：

```text
std_msgs/Header header                 # world，/clock
uint8 state
string state_name
string reason_code
string air_controller                  # takeoff_controller / lqr_tracker_node / none
string ground_controller               # ground_commander / none
string target_id
float32 target_xy_distance_m           # 无目标时 NaN
float32 target_obs_age_s               # 无目标时 NaN
bool tracking_milestone_met
uint8 IDLE=0
uint8 AIR_SEARCH=1
uint8 TARGET_ACQUIRED=2
uint8 GROUND_APPROACH=3
uint8 TRACKING_SUCCESS=4
uint8 MISSION_FAILED=5
uint8 ABORTED=6
uint8 INTERCEPT_CONFIRMED=7            # 阶段 B 保留，阶段 A 禁用
uint8 INFRA_FAILURE=8
```

## 四、执行后端与控制所有权

现有 `ground_car.sdf` 是无轮式驱动插件的单连杆车体；`ground_env.py` 和 `car_launch_controller` 靠 `set_model_state` 移动车。单纯新增 `cmd_vel` 发布者**不会让车运动**。本版固定上层命令口，并要求每个 run 只启用一个后端：

| 后端 | 阶段 | 唯一运动写入者 | 结果表述 |
| --- | --- | --- | --- |
| `kinematic_sim` | M3–M6 首条链路 | `ground_drive_adapter` 积分命令并写车体 `set_model_state` | 运动学仿真，不称动力学或实物验证 |
| `dynamic_sim` | 后续仿真 | 车体驱动插件或控制器 | 标定后称动力学仿真 |
| `hardware` | M8 | 车载驱动器 | 仅按实测能力表述 |

`kinematic_sim` 是**任务运行期的明确例外**：只有 `ground_drive_adapter` 可写本方车位姿。旧 `ground_env` 与 `car_launch_controller` 的写位姿循环在协同 run 中停用；`scenario_reset` 只在任务非运行期写本方车位姿。适配器报告服务调用失败并提供指令 watchdog；`ground_odom_adapter` 独立读取 Gazebo 实际位姿作为反馈。目标运动由独立 `intruder_driver` 实现，可写非被控目标位姿，场景中记录其轨迹与运动约束。

空中 setpoint 的所有权按阶段分配：起飞时 `drone_launch_controller`，确认起飞和 `release_control` 后由 `lqr_tracker_node` 接管，任务期仅 LQR 实际发布。核查**实际消息时间序列**，不能仅看 ROS Master advertiser 列表。交接期间保持 OFFBOARD 所需连续 setpoint，不能固定静默 0.2 s 制造空窗。记录双方最后/首次发布时间、最大间隔、MAVROS 模式。终止、目标失联或异常时由指定空中控制者持续发布经验证的安全 hold；不得将偏移归零后继续沿旧参考飞行。

地面 `ground_commander` 是 `/agc/ground/cmd_vel` 唯一发布者；目标/路径过期、终态和异常立即发零速。`ground_drive_adapter` 还要独立检测命令年龄 >0.2 s 并零速，以防上层失联。记录命令和实际位姿，确认车辆确实停住。

## 五、状态机与结果分类

```text
IDLE --start且门禁通过--> AIR_SEARCH --有效观测连续1 s--> TARGET_ACQUIRED
TARGET_ACQUIRED --目标/地图/车位姿有效且路径可用--> GROUND_APPROACH
GROUND_APPROACH --连续抵近跟踪窗口达成--> TRACKING_SUCCESS（阶段 A 终态）
任一非终态 --任务条件失败--> MISSION_FAILED
任一非终态 --人工急停--> ABORTED
任一非终态 --复位/时钟/TF/执行设施失败--> INFRA_FAILURE
```

start 门禁检查：单 world、时钟、TF、空地 odom、目标和地图源、地面后端、空中起飞/交接状态、场景复位。门禁未通过不得进入 AIR_SEARCH，记 `INFRA_FAILURE`。终态只能由下一次 run 的复位退出。`TARGET_ACQUIRED` 规划连续失败不能无限等待；`TRACKING_SUCCESS` 是阶段 A 终态，不再等待接触。阶段 B 状态转移待机构方案冻结后另定。

### 5.1 抵近跟踪成功

进入 GROUND_APPROACH 后，以下条件在同一连续 **5.0 s 仿真时间**窗口内成立：

1. 车中心到**目标地面投影**平面距离 ≤3.0 m；另行记录目标高度，不据平面距离推断可接触。
2. 目标真实观测年龄 ≤0.5 s、质量达到该来源已标定门槛；车 odom 年龄 ≤0.5 s。
3. 对**非目标障碍物**的几何净空不低于该场景预设的保护距离，且没有非目标碰撞体接触。
4. 逐帧记录车与目标速度、相对速度和距离。阶段 A 不设相对速度上限，因此只能称“持续近距跟踪”，不称“速度匹配”或“捕获”。

任一条件中断，窗口计时清零。时钟不推进时不累积成功时长。目标运动场景须先做可达性检查，避免拿物理上无法追上的轨迹评估控制器。

### 5.2 原因码与统计归属

| 状态 | reason_code | 条件 |
| --- | --- | --- |
| MISSION_FAILED | `SEARCH_TIMEOUT` | 搜索 60 s 无有效目标 |
| MISSION_FAILED | `TARGET_LOST` | 曾获得目标后观测连续丢失 >2 s；丢失期间先停车 |
| MISSION_FAILED | `PLAN_UNREACHABLE` | 输入有效但规划按场景预设次数重试仍不可达 |
| MISSION_FAILED | `APPROACH_TIMEOUT` | 进入抵近状态 60 s 未达成窗口 |
| MISSION_FAILED | `MISSION_TIMEOUT` | start 后 120 s 未成功 |
| MISSION_FAILED | `GROUND_COLLISION` | 车与非目标障碍指定碰撞体接触或经核查几何相交 |
| MISSION_FAILED | `SAFETY_STOP` | 安全停车且剩余任务时间内无法恢复；单次触发只记事件 |
| ABORTED | `OPERATOR_ABORT` | 人工终止或急停 |
| INFRA_FAILURE | `STARTUP_FAILURE`、`RESET_FAILURE`、`CLOCK_STALL`、`TF_INVALID`、`ODOM_INVALID`、`DRIVE_BACKEND_FAILURE`、`CONTROL_CONFLICT` | 平台、复位、时间或控制设施失效 |

同拍结算优先级：人工急停 > 已验证碰撞 > 基础设施失败 > 成功窗口完成 > 任务超时；其他同时事件仍完整落盘。保护距离违例单记 `CLEARANCE_VIOLATION`，不叫碰撞；紧急距离触发单记 `EMERGENCY_TRIGGER`，避免因阈值包含关系让两个失败码互相遮蔽。复位失败只属 INFRA_FAILURE，绝不进入任务失败分子。

工程初值：目标/odom 新鲜度 0.5 s，命令 watchdog 0.2 s，目标丢失容忍 2 s，抵近半径 3 m，连续窗口 5 s，搜索/抵近/总任务时限 60/60/120 s。地面车保护距离**待 M2 按车体几何与传感器标定**；v1.0 所写 0.9/0.7/2.4 m 不是当前地面环境的既有参数，不作为已验证阈值。每个场景在 run 前锁定具体阈值与配置哈希；不能看同一批结果后修改。

## 六、规划、失联与日志

`ground_planner` 输入包含目标地面接近点、有效地图、车当前姿态、车体膨胀半径及时间戳。目标位移 >1 m、地图版本变化、路径不可行或距上次规划 ≥2 s 时重规划；路径至少 1 Hz 重发，避免 2 s 重规划与 2 s 超时相撞。每次保存触发原因、输入与地图版本、规划耗时、路径和失败原因。未知栅格按场景配置固定为保守障碍或允许探索。

目标数组空表示本拍无目标；不能复制旧姿态并换新 stamp。目标、地图或路径暂时过期时地面先停，恢复后可在任务时限内继续；超过容忍窗结算相应任务失败。时钟停滞、TF 失效、驱动调用失败与控制冲突属于 INFRA_FAILURE。/clock 停滞由单调墙钟发现；仿真时长不在停钟期间增长。

每次 run 保存：唯一 run_id、契约/代码/SDF/场景哈希、目标源和驱动后端、参数与种子（没有则写 `unseeded`）、仿真与单调墙钟时间、TF 校准、空地 odom、目标、地图、goal、path、cmd、实际轨迹、状态事件、控制交接、启动/复位/清理结果。分列 `attempted_runs`、`infra_failure_runs`、`valid_task_runs`、`tracking_success_runs`、`mission_failure_runs`、`aborted_runs`；要求 `valid_task_runs = tracking_success_runs + mission_failure_runs`，`attempted_runs = valid_task_runs + infra_failure_runs + aborted_runs`。任务成功率为 `tracking_success_runs / valid_task_runs`，同时报告基础设施失败/全部尝试与人工终止/全部尝试。真实接触、几何相交、保护距离违例、过滤器触发分别报。

## 七、M1–M6 验收

| 门槛 | 可核查证据 |
| --- | --- |
| 世界和接口 | 单 world、单 /clock、TF 闭合；每个话题类型和实际发布者符合本文；车 odom 与 Gazebo 实际车体一致 |
| 执行 | 正向、转向、零速命令可使车按选定后端运动和停车；断开命令 ≤0.2 s 零速；起飞/LQR 交接无 setpoint 空窗 |
| 因果闭环 | 固定起点与地图，只改变空中目标/障碍输入，地面 goal、path、cmd 和实际轨迹出现可解释变化；无信息时安全停车 |
| 结果口径 | 至少各有一个成功、任务失败、基础设施失败和人工 abort 的可回放样例；状态与分母正确 |
| 重复性 | 简单固定场景连续运行并完整退出，每次尝试都有日志；未达到门槛的阶段不能标“已验收” |

字段、话题类型、坐标/时间语义、状态与结果类变动须升契约版本；仅调整已允许的场景工程阈值须在 run 前留配置哈希和理由。阶段 B 拦截方案单独冻结，不能以本版的 `TRACKING_SUCCESS` 追认拦截成果。
