## 二、实现要点

- **物理一致性（关键修正）**：AGC 世界原先只有固定 `pole_1/pole_2`，随机化障碍只进规划栅格、不进 Gazebo。现由生成器为每个场景产出配套 `world_<scenario_id>.world`（保留 sun/ground_plane/asphalt_plane/agc_car/intruder_uav，仅替换障碍模型），使物理障碍与 scenario obstacles 逐字段一致；launch 新增 `world_file` 直通 `mavros_posix_sitl.launch` 的 `world`，`agc_run_logger` 的 `world_hash` 改为对**实际加载的 world 文件**取哈希。
- **确定性**：主种子经 `sha256(f"{master_seed}|{split}|{family}|{index}")` 派生条目种子并做 split 命名空间隔离；浮点定点舍入、YAML/JSON 固定键序、`generated_at` 由种子派生，保证同一主种子逐字节重建（`--rebuild-check` PASS）。
- **可行性约束**：车/无人机 spawn 净空 ≥2.4m、目标保护距离 + 量化误差、膨胀栅格 BFS 可达性；故意不可达场景（四墙封闭）反向校验必须不可达；不满足则重采样并记录。
- **族与规模**（协议 `sample_size_plan`）：test = nominal 20 / obstacle_layout 12 / unreachable_closed 10 / boundary 10 / perception_fault 14 = 66；train 28 / validation 21（用于调参，布局与种子与 test 隔离）。
- **批跑器**：断点续跑（状态文件按 scenario_id）、重复种子检测（含 `pair_id` 配对臂例外）、基础设施失败重试 append-only、逐 run 记录 `run_id`/配置哈希/种子、三类分母恒等式核对、hash 一致性校验。

### 已记录的构造性缺陷与修正（协议 Rule：保留原结果、另起版本）
`perception_fault` 族 v1 把 `sigma_xy_m` 随机到约 0.47–0.66 m；而 confidence=`1-exp(-tol^2/(2*sigma^2))`（`tol=0.25`），要 `conf>=0.5` 须 `sigma<=0.2124`。故该族 14 条**构造上必然 conf<0.5**、0/14 全 `SEARCH_TIMEOUT`（退化臂）。
- **保留** v1 结果为“构造性缺陷”证据（上表）。
- **修正版** `manifest_percfault_v2.json`（14 条）：与 v1 同场景/同 world/同 seed，**仅更换感知标定**（`sigma_xy∈[0.10,0.30]` 等），构成配对对照；条目级 min-conf≥0.5 由 0/14 提升到 7/14、至少单通道≥0.5 为 10/14。其结果见 `batch_index_formal_percfault_v2.jsonl`（本文件“修正版结果”节）。

## 五之二、执行架构演进：Gazebo 常驻热切换

原批跑器每回合「清理→启动栈→起飞→交接→跑→停止」，实测 ~116 s/回合，其中约 80–90 s 是启动开销。
现改为**一次启动、组内连跑**（参考 RL 侧 `gazebo_env.py`/`train_dqn.py` 的热切换写法）：

- `scenario_reset` 新增 `/agc/scenario/dynamic_obstacles`（默认 false）；为 true 时按 `/agc/scenario_file` **动态删除旧障碍、spawn 新障碍**，并 bump `/agc/scenario/epoch`；默认 false 时行为与改动前逐位等价。
- 新世界 `worlds/agc_world_dynamic.world`（去掉固定 `pole_1/pole_2`，障碍全部动态 spawn）。
- `map_adapter`/`task_manager`/`intruder_driver` 在 `/agc/scenario_file` 变化时**自动重载**（栅格/安全接近几何/目标航迹）；`air_perception` 在 `/agc/perception/sensors_file` 变化时重载通道；`agc_run_logger` 在 attempt 起点**重建 meta**，保证每回合 `scenario_hash/seed/params` 与当回合一致。
- `start_agc_collab.sh` 新增 `--serve`（常驻）与 `--dynamic-obstacles`；`d1_batch_runner.py` 新增 `--hot-swap`：按 `(target_source, obstacle_source)` 分组（`/agc/targets` 只允许一个发布者），每组一次启动，组内逐回合只做「rosparam set 场景/感知/seed → reset → start → 等终态 → 记录」。

**热切换 pilot 验证**（`batch_index_hotswap_pilot*.jsonl`）：
- `perception_fault_v2` 3 回合（air_fusion 组）：116 s/回合 → ~69 s/回合；
- `unreachable_closed` 2 回合（gt_adapter 组）：`scenario_obstacles_present={present:6,total:6}`、`scenario_obstacles_ok=True`（`box_top/bottom/left/right`+`pole_1/2` **确实物理存在于 Gazebo**），终态 `PLAN_UNREACHABLE`，`meta.seed` 正确、`scenario_hash_match=True`、`world_hash_match=True`、`hash_mismatch=0`。

## 六、负例与未决边界

- **pilot 负例**：`perception_fault` 首例为 `SEARCH_TIMEOUT`（valid_task 的 mission_failure），非成功率满分；如实计入分母。
- **消融配对**：`remove_tracking_mechanism` 的 fusion 臂与 test nominal baseline 共享 `pair_id`/场景/种子，仅 `target_source` 不同；重复种子检测对配对臂放行。
- 未决：`hold_window_s` 收紧的“成功判据敏感性”臂未单独批跑（列为后续）；`generated_at` 为种子派生确定性时间戳。
