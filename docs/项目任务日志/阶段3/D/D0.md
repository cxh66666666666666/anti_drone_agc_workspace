## 二、成功/失败分类与真值判据

- 终态分类（M0 状态 → 统计分类）：`4 TRACKING_SUCCESS → tracking_success`、`5 MISSION_FAILED → mission_failure`、
  `6 ABORTED → aborted`、`8 INFRA_FAILURE → infra_failure`。
- 成功定义：终态 `TRACKING_SUCCESS`（地面车抵近并在 `hold_window_s=5.0` 内持续跟踪）。**不得表述为拦截完成**；
  `INTERCEPT_CONFIRMED`（state 7）在阶段 A 禁用，任何报告不得出现。
- 安全净空/碰撞结算一律以真值（`/gazebo/model_states`）为准；估计量只能作控制输入与性能指标。
- 净空阈值偏序：`emergency_m(0.35) < protection_m(0.80) < safe(2.4)`。
- 失败原因码分层：名义失败 `TARGET_LOST/APPROACH_TIMEOUT/SEARCH_TIMEOUT/MISSION_TIMEOUT/PLAN_UNREACHABLE/CLEARANCE_VIOLATION/EMERGENCY_TRIGGER/GROUND_COLLISION`；
  基础设施 `STARTUP_FAILURE/ODOM_INVALID/DRIVE_BACKEND_FAILURE/CONTROL_CONFLICT`；人工 `OPERATOR_ABORT`。

## 三、时间窗与三类分母

时间窗：`search_timeout=60s`、`approach_timeout=60s`、`mission_timeout=120s`、`hold_window=5s`、`target_lost_tolerance=2s`；
新鲜度：`target_max_age=0.5s`、`cmd_max_age=0.2s`、`goal_max_age=1.0s`、`odom_max_age=0.5s`、`path_max_age=2.0s`。
**超时一律计为失败**（valid_task 而非 success）。

分母恒等式（与 `summarize_runs.py` 一致，作为可审计约束）：

```
attempted_runs = valid_task_runs + infra_failure_runs + aborted_runs
valid_task_runs = tracking_success_runs + mission_failure_runs
```

- 注入的通信/感知/时钟故障若仿真正常且任务有结局，仍归 `valid_task_runs`；
- 启动、复位、日志损坏等基础设施故障单列 `infra_failure_runs`，**不得被静默重跑后抹去**（重试只追加）。
- 主指标 `tracking_success_rate = tracking_success / valid_task`；同时报告基础设施失败率与人工终止率（分母为 attempted）。

## 四、基线与预注册对照

| 基线 | 目标源 | 说明 |
| --- | --- | --- |
| `B_gt` | `gt_adapter` | 真值直供，无感知链路（无噪声，confidence=1） |
| `B_fusion` | `air_fusion` | 真值派生的多源观测门控 + 逆方差融合 |
| `B_noinject` | `gt_adapter` | 现有无注入栈，作为链路注入对照的零注入基线 |

预注册对照（配对：相同场景、目标轨迹与种子）：
- `C1`：`B_fusion` vs `B_gt`（多源门控与融合相对真值直供的成功率差）。
- `C2`：`randomized` vs `fixed`（场景分布消融）。
- `C3`：`without_tracking_mechanism` vs `full_stack`（去掉关键跟踪机制：以 `gt_adapter` 真值直供替代多源门控+融合）。

## 五、统计口径与输入格式

- 成功率：Wilson 95% 区间；失败模式：占比 + Wilson 95% 区间；配对效应：风险差 + bootstrap 95%（10000 次重采样）。
- 泛化 gap：`train_rate - test_rate`。
- **判定规则**：以配对效应量置信区间与预注册最小有意义差异（`min_meaningful_difference_pp=10`）比较判断证据是否充分，
  **不以“两组区间是否重叠”判定**。
- 输入：由 manifest（`experiments/d/manifest_*.json`）+ 各 run 的 `summary.json`/`meta.json`/`state_events.jsonl` 组成；
  每图表附原始 run 清单（run_id 列表），可由原始日志单命令再生。协议 `data_dictionary` 给出字段级定义。

## 七、冻结与版本可追溯

- 冻结脚本 `d0_freeze.py` 对协议、schema、`agc_params.yaml`、`perception_sensors.yaml`、场景模板、`agc_collab.launch`、
  `start_agc_collab.sh`、`summarize_runs.py` 取 sha256，写入 `experiments/d/protocol_v1_hashes.json`（含 `combined_hash`）。
- `python3 d0_freeze.py --check` 复核：任一被冻结对象改动即 FAIL → 需另起 `eval_protocol_v2`，不得就地修改。
- 冻结在 D1 编排/launch 改造完成后、正式测试集批跑之前执行（保证“先锁协议，后跑数据”）。

## 八、未决边界

- 采样运行成本与方差在 D1 试跑后回填；正式样本量以 `protocol_v1` 预注册值锁定，不足则如实标注区间宽度。
- `hold_window_s` 收紧的“成功判据敏感性”消融仅作稳健性检验，不作为主结论。
- 本阶段为仿真分布与所列模型/预算下的结论，不含真实硬件与拦截机构。
