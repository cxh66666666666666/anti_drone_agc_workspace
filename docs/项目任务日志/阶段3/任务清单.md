## 二、统一执行与证据规则（适用于所有任务）

1. **先锁协议，后跑数据**：每组实验提交场景清单、分布和取值范围、训练/验证/测试划分、随机种子、样本量、主要指标、失败定义、基线、预定对照和排除规则。冻结配置及代码/SDF/场景/模型哈希后再跑正式集；调参只用训练/验证集。正式测试集若发现协议缺陷，保留原结果，另起版本和新测试集。
2. **记录尝试分母**：`attempted_runs = valid_task_runs + infra_failure_runs + aborted_runs`；`valid_task_runs = tracking_success_runs + mission_failure_runs`。注入的通信/感知/时钟故障若仿真正常且任务有结局，仍归 `valid_task_runs`；启动、复位、日志损坏等基础设施故障单列。报告任务成功率 `tracking_success/valid_task`，同时报告基础设施失败率和人工终止率，逐个给原因。
3. **配对可复现**：A/B 与基线使用相同场景、目标轨迹和种子配对；不同随机源独立编号，避免一次随机调用改变其他变量。每个 run 留 `run_id`、配置/代码哈希、目标源、注入时序、仿真/单调墙钟时间、真值、观测、估计、控制、状态事件与退出清理记录。原始日志只追加，不覆盖历史证据。
4. **指标可审计**：明确指标定义、采样频率、对齐容差、缺失值与截尾处理；图表能由原始日志单命令再生。名义、故障注入、基础设施失败分开制表。安全净空/碰撞结算仍以真值为准；估计量只能作为控制输入和性能指标。
5. **验收流程**：每项先做确定性单元/离线重放，再做小规模集成冒烟，最后在冻结测试集批跑；验收文档给命令、目录、版本哈希、样本分母、核验器 PASS/FAIL、负例和未决边界。状态仅用「未开始 / 进行中 / 已验收 / 阻塞」；未跑完不得标已验收。
6. **契约变更检查点**：不改变现有八个协同话题及其时间/坐标/状态语义时可保持 v1.2；若多目标 ID 规则、预测航迹输出时间戳、低置信输出、安全仲裁或新正式话题改变契约，先形成 v1.3 变更表、迁移/回归清单和旧消费者兼容测试，再实现与验收。不得以“内部话题”绕过实际语义变更。

## 六、联合验证、顺序与阶段退出条件

1. **顺序**：D0 → D1 → D2 管线可用；随后 A0/A1 与 B0/B1 可分别推进；A2 在契约检查点后进行；A3 和 B2 使用相同 D 测试协议；最后联合验证。每个任务独立留验收记录，不因其他任务通过自动标记完成。
2. **联合组 J0 / 未开始**：选取名义、低信噪比、多目标交叉、短/长遮挡、突发丢包、时钟异常及组合边界；运行现有栈、仅 A、仅 B 注入、A+B 四种配对组。对比任务终态、估计一致性、控制空窗与失效恢复，检查故障相互作用。若采用新的契约版本，对 M1–M6 和 N1–N4 受影响项做当前代码回归；N3 的真正不可达场景使用新封闭障碍，旧批次只作历史引用。
3. **退出条件**：D/A/B/J0 的协议、代码、配置、原始批次、可重生统计图、失败分类及回归记录齐全；所有冻结测试组均有完整分母和 95% 区间；没有未解释的发布者冲突、历史数据覆盖、测试集泄漏或 `INTERCEPT_CONFIRMED`。性能未达到预期可如实验收“边界已量化”，不得把负结果改写成成功。
4. **成果表述**：阶段3能支持的结论限定于仿真分布和所列模型/预算；论文或软著素材可整理，但不以投稿/申请作为技术任务的验收条件。
