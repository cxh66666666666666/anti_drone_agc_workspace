# N4 融合与控制故障边界 验收 v1

> 2026-10-06；依据 [下一阶段任务清单.md](../../项目指导书/下一阶段任务清单.md) 的 N4（P1）与 [M0_接口契约_v1.2.md](../阶段1/M0/M0_接口契约_v1.2.md) 第四、八节，并回应 [M4 §八.3](../阶段1/M4/M4_目标识别与多源融合验收_v1.md)、[M5 §八.1/§八.4](../阶段1/M5/M5_控制权交接验收_v1.md) 的未决项。证据根目录：`experiments/agc_runs/`。本版只覆盖 N4：**建立冷启动冲突规则、收紧 `release_control` 后的 advertiser 生命周期，并注入高置信离群 / 单通道失效 / 目标超时 / 交接异常四类故障**，逐组留「观测门控 / 实际控制源 / 停车时延 / 结局」，正常组无新增误报。不推进 N5/N6，不宣称拦截完成。

## 一、任务口径与诚实说明

N4 要求补齐两类故障边界：

1. **融合冷启动冲突**：`air_fusion` 无历史估计时以「最高置信通道」作空间一致性参考；M4 §八.3 记录该通道异常时可能误拒正常通道（M4 用低置信通道注入规避）。
2. **控制侧故障边界**：M5 §八.1 记录 `drone_launch_controller` 释放控制权后仍保留 setpoint advertiser，无法仅凭发布者列表区分 advertiser 与实际发布者；M5 §八.4 记录 `*_TIMEOUT` 安全路径仅由代码核查。

**诚实说明**：

1. 感知仍为 **Gazebo 真值派生的感知仿真**（`air_perception` 加噪 + 几何门控），**不是真实视觉/雷达识别**；`INTERCEPT_CONFIRMED` 全 run 未出现。
2. 冷启动冲突规则的判定是**几何/统计的**（按 `gate_m` 对候选做单链聚类）；「冷启动」定义为**无 `ref_hold_s` 内历史融合估计**。`air_fusion` 自栈启动即运行，故冷启动发生在**首次观测**（本场景在起飞阶段）；若故障在任务 `start` 后才注入，此时已有历史，属稳态冲突（由历史参考处理，见 §四.撤换说明）。
3. 超时组是一次**参数注入**（run 前冻结覆盖 `limits/mission_timeout_s`），非自然超时；它验证 `*_TIMEOUT` 的**共享安全路径**（停车 + 空中 hold + 终态），不改判据。
4. 交接异常组以**终止 `lqr_tracker_node`** 制造 setpoint 空窗（设计内的控制故障注入）；空中侧 PX4 随之退出 OFFBOARD（failsafe），**地面任务不受影响**（终态仍由地面侧结算）。
5. 本版**不新增话题/消息、不改坐标/时间基准、不改状态机终态与判据**，`contract_version` 保持 `agc-m0-v1.2`；新增为参数与诊断日志字段（见 §二）。

## 三、实现

**融合冷启动冲突规则（实时链路 C++，[air_fusion.cpp](file:///home/ubuntu/anti_drone_agc_workspace/src/air_ground_core/src/air_fusion.cpp)）**：

- `fuseTargets()` 参考点选择扩展：有历史（`ref_hold_s` 内）→ 最近融合估计（不变）；**无历史（冷启动）**→ 按 `gate_m` 对候选做**单链聚类**，取最大簇质心作参考。
- 若候选数 ≥2 且**最大簇成员数 < `cold_start_min_agree`**：判**冷启动歧义**，发布空 `/agc/targets` 并记 `result=cold_start_ambiguous`、`ref_source=ambiguous`、`cluster_sizes`，**不把无法判定的冲突当作高置信输出**。
- 单候选（仅 1 通道可用）不判歧义，正常输出（降级运行）。
- 其余（新鲜度/置信度门控、`gate_m` 一致性、逆方差加权、相关噪声协方差下界、空发布语义、障碍融合）**逐条不变**。

**advertiser 生命周期收紧（实时链路 C++，[drone_launch_controller_node.cpp](file:///home/ubuntu/anti_drone_agc_workspace/src/drone_launch_controller/src/drone_launch_controller_node.cpp)）**：

- `releaseControlCallback`：`takeoff_controller_.releaseControl()` 后 `local_pos_pub_.shutdown()`——释放后不再保留 setpoint advertiser，使发布者列表与实际发布者一致（回应 M5 §八.1）。
- `takeoffCallback`/`armMotorsCallback` 入口重新 `advertise` 该话题（同节点同话题为幂等），保证 `--repeat/--cycles` 多 attempt 仍可起飞。

**注入与编排（非实时链路）**：

- `agc_collab.launch` 新增 `mission_timeout_s`（覆盖 `limits/mission_timeout_s`）与 `perception_fault_sensor`/`perception_fault_bias_m`（启动前预置感知故障）。
- `scripts/start_agc_collab.sh` 新增 `--timeout-inject <秒>`、`--handover-inject <秒>`（交接后 `rosnode kill /lqr_tracker_node`）、`--fault-preset <通道>`/`--fault-preset-value <米>`。
- 融合侧复用既有 `m4_inject.py`（`conflict`/`loss`）。

**离线核验（非实时链路）**：

- [verify_fusion.py](file:///home/ubuntu/anti_drone_agc_workspace/src/air_ground_core/scripts/verify_fusion.py) 增 `outlier`（冷启动歧义、不输出、不误跟、终态为超时类）与 `single_channel`（单源融合仍输出、无 `gate_rejected_all` 误报）。
- [verify_control_authority.py](file:///home/ubuntu/anti_drone_agc_workspace/src/air_ground_core/scripts/verify_control_authority.py) 增 `timeout`（`MISSION_TIMEOUT` 终态）与 `handover`（交接后 advertiser 不残留 + 控制空窗被记录）；并新增通用项 **B5 交接后 advertiser 不残留起飞控制器**。

## 五、结果（逐组 PASS/FAIL）

### 5.1 冷启动冲突规则（`verify_fusion.py --mode outlier`，PASS=7 FAIL=0）

批 `_n4_coldoutlier2_…`：`cold_start_ambiguous` **1318** 拍；`/agc/targets` **nonempty=0**（不发高置信目标）；`tracking_frames=0`（地面**未向歧义目标抵近**）；终态 `MISSION_FAILED/SEARCH_TIMEOUT`。对比：首次 `--inject`（稳态）组融合正常跟随真值——说明差别确由冷启动路径处理。

### 5.2 单通道失效降级（`verify_fusion.py --mode single_channel`，PASS=9 FAIL=0）

批 `_n4_singlechan_…`：`air_eo_front` 全丢失段 **单源 fused tick=71**（融合仍由 `air_ir_top` 支撑输出）；`gate_rejected_all` **0**（正常通道不被误拒）；`/agc/targets` nonempty=861；goal 跟随中位 0.138 m；`TRACKING_SUCCESS`。

### 5.3 超时安全路径（`verify_control_authority.py --mode timeout`，PASS=14 FAIL=0）

批 `_n4_timeout_…`：`final_state=5 MISSION_FAILED`，`reason=MISSION_TIMEOUT`；终态后地面零速停稳（300 拍窗口 `max|vx|=0.0000`、位移 0.0001 m）；空中 hold 通过（`hold_triggered=true, hold_ok=true`，最大偏差 1e-4 m）；唯一控制源（地面 `ground_commander`、空中 `lqr_tracker_node`）与阶段字段一致。**首次以真实 run 覆盖 `*_TIMEOUT` 安全路径**（此前仅代码核查）。

### 5.4 交接异常与 advertiser / 发布者可区分（`verify_control_authority.py --mode handover`，PASS=13 FAIL=0 SKIP=2）

批 `_n4_handover_…`：

- **advertiser 生命周期**：B5 交接后最后 `setpoint_publishers=[]`（正常组为 `['lqr_tracker_node']`，均**不含** `drone_launch_controller`）——收紧后发布者列表与实际发布者一致。
- **控制空窗**：`air_control_authority.jsonl` 记 `control_conflict` **1** 条且 `setpoint_gap_s > 0.20 s`；`active_controller=lqr_tracker_node`（持久判定，实际发布者已消失由 `control_conflict` 标示）。
- `B3`/`C2` SKIP 系注入语义（交接后 PX4 退出 OFFBOARD、LQR 被终止无 setpoint 流可验 hold）；地面侧 C4 零速停稳通过。人工急停/失联组的 hold 仍由既有 `nominal` 模式覆盖（① PASS）。

## 六、结果口径与措辞

- 冷启动歧义的「不输出」是**安全行为**（不跟随无法判定的目标），非感知丢失的真实语义；`out_of_fov`/`stale` 等仍为几何/门控判据。
- ② 的 `SEARCH_TIMEOUT` 由**注入故障**主导，属设计内失败，已打 `preset_fault` 标签；③ 的 `loss` 注入、④ 的 `timeout` 注入、⑤ 的 `handover` 注入、⑥ 的 `writer` 注入同理，**不计入名义成功率分母**。
- 阶段 A 终态为 `TRACKING_SUCCESS`（地面车抵近并持续近距跟踪），**不得表述为拦截完成**；全部 run 未出现 `INTERCEPT_CONFIRMED`。
- ⑤ 交接异常下 PX4 退出 OFFBOARD 属 PX4 failsafe 行为；本版**只记录**该边界（未新增空中独立安全仲裁），见 §八。

## 八、未决事项

1. **冷启动窗口与时序**：`air_fusion` 自栈启动即运行，「冷启动」只在首次观测瞬间存在；本版用「启动前预置故障」稳定复现。若后续把 `air_fusion` 改为按任务 `start` 复位历史，则可用运行期注入复现冷启动，语义更贴近任务生命周期，留待需要时再定。
2. **冷启动歧义策略为「不输出」**：本版不发低置信目标（避免被 `confidence_min` 消费而误跟）。若业务需要「降级但仍跟踪」，应新增低置信标记与消费者侧策略，属契约/判据变更，需升版讨论。
3. **空中侧独立安全仲裁缺失**：交接后控制空窗只由 `air_control_bridge` 记录（`/agc/air/control_conflict`），无节点据此接管或使地面停车；PX4 failsafe 兜底。若要「空中失控→任务安全终止」，需新增仲裁与契约，未在 N4 范围。
4. **单通道失效未做「先双通道后降级」的连续性专项**：本轮为运行期注入（start+8s），已呈现单源降级与无新增误报；未量化降级瞬间的坐标/时间戳连续性。
5. **cluster 参数为工程取值**：`gate_m=1.5`、`cold_start_min_agree=2` 沿用既有门限，非标定值；接入更多/更独立通道时应重标定。
