> 2026-10-06；依据 [下一阶段任务清单.md](../../项目指导书/下一阶段任务清单.md) 的 N3（P1）与 [M0_接口契约_v1.2.md](../阶段1/M0/M0_接口契约_v1.2.md) 第四节。证据根目录：`experiments/agc_runs/`。本版只覆盖 N3：**按同一地图与分辨率修正目标格可行化，区分「可达但栅格落点错误」与「确实无路」**，不降低保护阈值，回归 M3/M4/M6。不推进 N4 及以后。

## 一、任务口径与诚实说明

N3 要求：M3/M4/M5/M6 均记录 `safeApproachPoint` 按连续几何净空回退后，目标格仍可能被 A* 膨胀图阻塞。需按同一地图与分辨率修正目标格可行化，区分「可达但栅格落点错误」与「确实不可达」；固定「目标贴障但有路」与「确实无路」两组，前者有 path、车安全抵近且净空达标，后者稳定给出 `PLAN_UNREACHABLE`；**不降低保护阈值**，回归 M3/M4/M6。

**诚实说明**：

1. **不降低保护阈值**：保护距离仍是 `clearance.protection_m=0.80`；膨胀量 `dilate_m = max(planner.inflation_m, protection_m) = 0.80` 不变。「可行格」沿用膨胀图定义（格中心净空 ≥ `dilate_m`），N3 只在目标格被阻塞时就近换格，**未放松任何阈值**。
2. **M6 冻结报告中「不可达」场景行为变化**：`scenario_unreachable.yaml`（目标贴 `pole_2`）在原代码下结算 `MISSION_FAILED/PLAN_UNREACHABLE`，其本质是**「可达但栅格落点错误」**；N3 修复后该场景在**当前代码**下变为 `TRACKING_SUCCESS`（见 §5.3）。M6 冻结论文与报告（旧代码、`agc_params_hash=dd4b059c…`）不改，作为该状态的**历史记录**保留；「确实无路」改由 N3 新增的封闭场景 `scenario_truly_blocked.yaml` 承载。
3. 本版**不改既有 8 个协同话题的语义、状态机、判据与坐标/时间基准**，`contract_version` 保持 `agc-m0-v1.2`；未新增话题，仅新增一个规划参数与规划日志字段（见 §二）。
4. 阶段 A 终态仍为 `TRACKING_SUCCESS`（地面车抵近并持续近距跟踪），**不得表述为拦截完成**；全部 run 未出现 `INTERCEPT_CONFIRMED`。

| `agc.planner.goal_adjust_max_m` | 1.0 | 目标格可行化搜索半径（m）：目标格被阻塞时在切比雪夫半径 R 内就近取可行格 |

规划日志 `planner_log.jsonl` 成功行新增字段 `goal_adjusted`（bool）：`true` 表示原始目标格被膨胀图阻塞、已就近取可行目标格；`false` 表示目标格原本可行。规划失败新增原因 `goal_cell_blocked_no_feasible`（目标格被阻塞且半径 R 内无任何可行格）。

## 三、实现（实时链路 C++）

**`ground_planner`（改，[ground_planner.cpp](file:///home/ubuntu/anti_drone_agc_workspace/src/air_ground_core/src/ground_planner.cpp)）**：

- 新增匿名命名空间函数 `nearestFeasibleCell(blocked, goal_c, R, out)`：在切比雪夫半径 `R` 内按**欧氏距离**取最近的**可行格**（`buildBlocked` 定义：格中心到障碍净空 ≥ `dilate_m`）。返回 false 表示半径内无可行格。
- `plan()` 新增出参 `bool* goal_adjusted`。目标世界点映射到格 `goal_c` 后，**若该格被膨胀图阻塞**：取 `R = ceil(goal_adjust_max_m / res) = 2`；命中可行格 → `goal_c` 换为该格、路径终点取**该格中心**、`*goal_adjusted=true`；半径内无可行格 → `reason="goal_cell_blocked_no_feasible"`、返回 false。目标格原本可行时行为与旧版**逐位一致**（终点仍为 `goal` 精确世界点）。
- `tick()` 同步传入 `goal_adjusted` 并写入 `planner_log.jsonl`。

**设计要点**：修正发生在**规划输入侧的目标格**，起终点仍在同一张 `buildBlocked` 膨胀图上由 A* 判定连通；因此「可达但落点错」会换格成功，「确实无路」（如目标被墙围住）仍稳定失败。`safeApproachPoint` 的连续几何逻辑未改（其输出仍作目标世界点，由 `plan()` 做栅格可行化）。

## 八、未决事项

1. **M6 冻结论文与当前代码的语义错位**：M6 冻结报告仍把贴障场景记为「不可达」（旧代码/哈希），当前代码下该场景可达。若后续要让 M6 场景集与当前代码对齐，应把「不可达」重新锚定为封闭障碍场景（N3 已提供 `scenario_truly_blocked.yaml`），并在契约升版时更新场景哈希与报告。
2. **`goal_cell_blocked_no_feasible` 分支未被端到端场景命中**：B 组走 `astar_no_path`（目标格本身可行但与车分处墙内外），未触发「目标格被阻塞且 R 内无可行格」。如需覆盖该分支，可构造目标格落在稠密障碍内、且 R=2 邻域全阻塞的场景。
3. **目标格可行化只调整目标格**，不处理其他不可达形态（如起/终点均在可行域但无连通路径）；后者仍由 A* 判定，不在 N3 范围。
4. `safeApproachPoint` 的连续几何与栅格可行化仍为**两套逻辑**（前者产出世界点、后者做栅格化）；N3 通过目标格换格弥合落差，未把回退余量改为 `≥ protection + res/√2`（M6 §八.2 提出的另一方案）。
