## 一、任务口径与诚实说明

N2 要求：无人机跟随移动目标并保持安全距离带；在「LQR 是唯一 setpoint 实际发布者」的约束下，将**新鲜**目标观测变为**可选**跟随参考；覆盖静止、匀速、转向、越界、失联与恢复；「带内无持续摆动、失联不追旧目标、无双发布者/控制空窗」。

**诚实说明**：

1. 阶段 A 终态仍为 `TRACKING_SUCCESS`（地面车抵近并持续跟踪），**不得表述为拦截完成**；全部 run 未出现 `INTERCEPT_CONFIRMED`。
2. 无人机仅提供**位置跟随**（水平安全带 + 定高），**不替代地面任务终态**；路径规划仍在地面，地面唯一执行口仍为 `/agc/ground/cmd_vel`。
3. 跟随为**可选**能力：`air_follow` 仅在脚本 `--follow` 时启动，默认关闭，既有 M1–M7 场景不受影响（见 §5.4）。
4. 本版**不改既有 8 个协同话题的语义、状态机、判据与坐标/时间基准**，`contract_version` 保持 `agc-m0-v1.2`；新增的是**内部协同话题**（见 §二）。

## 三、实现（实时链路 C++）

**`air_follow`（新，[air_follow.cpp](file:///home/ubuntu/anti_drone_agc_workspace/src/air_ground_core/src/air_follow.cpp)）**：订阅 `/agc/targets`、`/agc/air/odom`、`/agc/task/state`，把新鲜目标观测变为**可选跟随参考**：

- **带内悬停**：`safe_min ≤ d ≤ safe_max` 时冻结保持点（进入带时锁存），不随无人机微漂移而持续摆。
- **过远跟近 / 过近退离**：参考沿「无人机→目标」方向前进 / 反向后退，每拍**至多 `max_step_m`**，方向取自目标而非无人机相对目标的径向——避免参考随无人机漂移旋转（否则绕圈）。
- **失联/未激活**：目标年龄超 `ref_max_age_s`（或任务非运行期）时**冻结在最近保持点，不追旧目标**。
- 高度恒定 `altitude_m`；参考跳变按 `max_step_m` 限幅。
- 逐帧落 `air_follow_log.jsonl`：目标/无人机位置、`distance_m`、`band_mode`、参考、`target_age_s`、`valid`、`task_state`。

**`lqr_tracker_node`（改，[lqr_tracker_node.cpp](file:///home/ubuntu/anti_drone_agc_workspace/src/lqr_trajectory_tracker/src/lqr_tracker_node.cpp)）**：新增可选消费 `/agc/air/follow_ref`（`follow_enabled` 时订阅）；参考在超时（`follow_timeout_s`，默认 0.5 s）内新鲜则**覆盖基础轨迹参考**（速度置零），否则回退基础 `step` 悬停。**setpoint 唯一实际发布者仍是本节点**；跟随参考只是其输入之一。

**编排**：`agc_collab.launch` 增 `follow_enabled` 参数与条件包含的 `air_follow` 节点；`lqr_tracker_sim.launch` 增 `follow_enabled/follow_timeout_s`；`start_agc_collab.sh` 增 `--follow`（同时传给两处），并把 `air_follow` 纳入清理/残留名单。

## 五、结果（`verify_n2_follow.py`，PASS=30 FAIL=0）

### 5.1 安全带行为

- **静止（带内悬停）**：`band_mode` 计数 `approach=79 / hold_in_band=181`；末个 valid 距离 **3.25 m** ∈ [2.0, 3.5]；valid 距离中位 3.25 m、范围 3.15–4.59 m。无人机先跟近进入安全带后带内悬停。
- **匀速/转向/越界**：`approach=171 / hold_in_band=72 / retreat=54`——目标远离时跟近、带内保持、目标靠近（最近 1.87 m）时退离三者均出现；末个 valid 距离 2.36 m（带内）。
- **模式与距离一致**：三场景 valid 样本模式/距离不一致 **0**；`approach/retreat` 抖动 **0**（即**带内无持续摆动**）。

### 5.2 失联冻结与恢复（loss）

- 失联窗内 `band_mode=hold_no_target` 样本 **30**；窗内无人机水平位移 **（0.35, 0.44）m ≤ 1.0**——**失联冻结、不追旧目标**。
- 失联后恢复：失联窗之后再次出现 valid 跟随样本 **132** 个；任务未 `TARGET_LOST`（1.5 s < 容忍窗 2.0 s），终态 `TRACKING_SUCCESS`。

### 5.3 高度 / 参考跳变 / 发布者 / 控制空窗

- **高度保持**：三场景 valid 期无人机高度 2.05–2.18 m（期望 2.00±0.30）。
- **参考跳变限幅**：相邻参考最大位移 0.56–0.60 m ≤ `max_step_m` 0.60。
- **唯一实际发布者 / 无控制空窗**：`air_control_authority.jsonl` 显示实际控制器恒为 `lqr_tracker_node`、`control_conflict=false`、最大 setpoint 空窗 0.020–0.064 s ≤ `setpoint_gap_max_s` 0.2；`air_handover.json` 交接 `hold_verified=true`。

### 5.4 回归（默认关闭，不影响 M1–M7）

跟随为**可选**：无 `--follow` 时 `air_follow` 不启动、不发布 `/agc/air/follow_ref`，LQR 不订阅跟随参考。回归批次 `_n2_reg_nominal_20261006T065338`（无 `--follow`）：`TRACKING_SUCCESS`、`audit_ok=true`、`any_leftover=false`，`/air_follow` 不在节点清单、无 follow_ref 话题——**既有 M1/M2/M5/M6 的实时链路行为不变**。

## 六、结果口径与措辞

- 无人机跟随是**位置保持**（水平安全带 + 定高），**不替代地面任务终态**；阶段 A 终态仍称 `TRACKING_SUCCESS`。
- 失联由**注入**（`/agc/target/enabled=false`）产生；失联窗 1.5 s 短于容忍窗 2.0 s，故未结算 `TARGET_LOST`（若要演示失联超容忍窗→`TARGET_LOST`，见 [N1.md](N1.md) 与 [M4 §5.4](../阶段1/M4/M4_目标识别与多源融合验收_v1.md)）。
- 三场景仅目标运动不同；目标速度（0.4 m/s）低于无人机可跟随上限，用于稳定展示带内保持。

## 八、未决事项

1. **跟随带宽与无人机速度**：PX4 位置环对「近距参考」响应较慢，故 `max_step_m` 取 0.6（参考前视量）以保证跟近速度；跟近末段仍有约 0.2–0.3 m 稳态滞后（带宽 [2.0,3.5] 内，未持续摆动）。
2. **参考帧**：`air_follow` 以 `world` 计算并发布，LQR 以 `map` 消费；本仿真 `world≈map`（标定 `dyaw≈2.9°`、`t≈(−0.07,0.03,0.09)`），未做显式坐标变换。若后续 `world≠map` 需在 LQR 侧变换。
3. **失联超容忍窗→`TARGET_LOST`** 与 **急停（`/agc/task/abort`）** 下的跟随行为未在本版单独构造（急停时任务转终态 → `air_follow` 冻结保持点，语义已由 §三覆盖）。
4. **新增内部话题未登记契约**：`/agc/air/follow_ref`、`/agc/air/follow_valid` 不在 M0 §8 冻结表；如需正式登记在契约升版时补。
