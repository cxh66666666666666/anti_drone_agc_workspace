# 阶段2 总结：无视觉条件下的后续工作方向

> 2026-10-06。本文登记阶段2（N0–N6）完成后的**方向性讨论结论**，作为下一阶段输入；不改契约、不替代 [阶段1/总结.md](../阶段1/总结.md) 与 [M0 接口契约 v1.2](../阶段1/M0/M0_接口契约_v1.2.md)。

## 一、背景与定位

- 阶段2 的 N0–N6 已全部验收（见 [N0](N0.md)–[N6](N6.md)），系统闭环可跑：单世界/时钟/TF、LQR 跟踪、真值派生多源融合、无人机跟随、地面 A*/目标格可行化、单机 RL 评估、故障注入与安全状态、目标机 iris 视觉。
- 但**现状仍偏「demo」**：固定场景验收、感知为真值派生、样本量小、链路理想、结论多以「固定样例成功率」表述。
- 阶段1《总结》决策 1 明确**不接真实相机/雷达、不实现视觉识别**；决策 4 **不做拦截机构**；决策 3 规划在地面。**因此后续工作必须在「非视觉」前提下展开。**

结论：没有视觉不等于没有可做的工作。把「非视觉感知 + 系统级可靠性 + 评估科学化」做扎实，正是把 demo 推向「**有边界、可复现、可写论文/软著**」的路径。

## 二、讨论结论（本次选定方向）

经讨论，优先推进 **A + D + B** 三个方向；C/E/F 登记为后续备选（见 §四）。

### A. 非视觉感知与目标跟踪的鲁棒化（主线）

- **现状可复用**：`air_perception`（真值派生：加噪/延迟/丢包/离群 + N1 的 FOV/量程门控）、`air_fusion`（新鲜度/置信度/空间一致性门控 + 逆方差加权 + N4 冷启动冲突规则）、`perception_sensors.yaml`、`verify_fusion.py`。
- **拟做**：
  1. **跟踪滤波**：把融合输出升级为带状态估计的跟踪器（EKF/UKF 或 CV/CA/IMM），输出位置+速度+协方差（`/agc/targets` 已有 `twist`/`covariance` 字段可承载），**不改话题语义**。
  2. **数据关联与航迹管理**：多目标、最近邻/概率关联、航迹起始/维持/删除；显式处理虚警/漏检。
  3. **不确定性加厚**：相关噪声、遮挡/短时丢失、目标机动；多传感器布置（前视/顶视/测距，仍为**真值派生仿真**）。
- **指标**：RMSE / NEES（估计一致性）、漏检率、虚警率、航迹纯度、失跟率、重捕获时延。
- **边界场景**：目标机动、遮挡、低信噪比、多目标交叉。
- **兼容性**：不接真实视觉、规划仍在地面、终态仍 `TRACKING_SUCCESS`。
- **依赖**：无（全部仿真/离线），可与 B 并行。

### B. 通信与时间链路级仿真（正交补强）

- **现状可复用**：N4 的故障注入（`m4_inject.py`）与编排脚本、`air_control_bridge` 的 setpoint 空窗统计、`/clock` 停摆审计。
- **拟做**：
  1. **链路模型**：延迟分布/抖动、突发丢包（Gilbert-Elliott）、带宽整形、消息优先级与降频。
  2. **时间模型**：时钟偏斜/漂移、`/clock` 停摆/跳变对状态机与融合的影响。
  3. **扫参**：链路质量 → **控制空窗时长/比例、交接与终态成功率、跟踪中断次数与时延** 的敏感性曲线。
- **指标**：控制空窗、交接成功率、跟踪连续性随链路质量的敏感性。
- **兼容性**：不新增/改话题语义；契约不变。

### D. 评估科学化与统计严谨（可信度）

- **现状可复用**：`summarize_runs.py` / `aggregate.json`、`verify_*.py`、N5 的 `n5_ground_scenarios`（布局隔离）与 `verify_n5.py`。
- **拟做**：
  1. **随机化大样本 / 参数扫描（fuzz）**：目标运动、初始位姿、障碍布局、故障参数分布。
  2. **训练/验证/测试隔离**（N5 已起步）+ 独立测试集。
  3. **统计**：成功率 **Wilson 置信区间**、样本量与显著性、**失败分类学（taxonomy）**、消融。
- **指标**：分布上的成功率 + 置信区间、泛化 gap、失败模式占比。
- **直接收益**：把 N5 已量化的「地面跨布局泛化 0%、样本小」升级为统计口径结论。
- **依赖**：需跑量（Gazebo 批跑），但分析离线；建议**先行**（成本低、提升后续所有结论可信度）。

## 三、建议执行顺序

1. **D 先行**：搭好随机化批跑 + 统计口径，作为 A/B 的评估底座。
2. **A 与 B 并行**：A 出方法/边界，B 出正交的系统敏感性；两者共用 D 的评估口径。
3. 每项均在 run 前锁定场景/参数/种子与哈希；分别报告名义、故障注入、基础设施失败，保持 `attempted = valid_task + infra_failure + aborted`。

## 四、未选方向（登记为后续备选）

- **C 任务与决策层**：搜索/覆盖规划、丢失后重捕获、多目标与任务分配、人机接管/handover、风险约束规划（滚动时域/MPC）。指标：任务成功率-时间、重捕获时延、分配 gap。
- **E 地面侧与多车/动障**：多车协同、动态障碍、在线重规划、LiDAR 占据栅格建图（非视觉）、保护距离在线标定。指标：多车冲突/死锁、地图一致性、重规划时延。
- **F 系统可靠性/安全**：看门狗、降级模式、安全过滤/可达性、FMEA、日志可审计可复现、实时性。指标：故障检出/误报率、恢复时间。
