# DQN 避障训练

## 启动

先启动只含感知、不含规则规划器的训练环境。障碍物坐标可按场景替换：

```bash
./scripts/start_sim.sh lqr --training --headless \
    --obstacle 0,-3,5 --obstacle 0,3,5
```

仿真完成起飞并开始 LQR 跟踪后，在另一个终端启动训练：

```bash
source /opt/ros/noetic/setup.bash
source devel/setup.bash
python3 src/rl_obstacle_avoidance/scripts/train_dqn.py
```

默认训练 300 个 episode，每个 episode 最多 450 步。epsilon 按环境步线性衰减，
默认以每集最多 150 个有效步估算衰减预算，在该预算的 50% 时从 `1.0`
降至 `0.05`（可通过 `--epsilon-decay-steps` 显式指定衰减步数）。
快速检查管线时可以显式缩小预算：

```bash
python3 src/rl_obstacle_avoidance/scripts/train_dqn.py \
    --episodes 5 --max_steps 20 --eval-interval 5 --eval-episodes 1
```

快速检查只验证训练管线，不用于判断策略效果。

### 复杂场景 goal mode

复杂场景使用 A* 规划全局航点、DQN 输出局部偏移。A* 只读取 `--obstacle`
定义的 a 柱，b 柱只由局部感知处理：

```bash
./scripts/start_sim.sh lqr --training --headless --goal-mode \
    --obstacle 5,0,5 --obstacle 10,0,5 \
    --obstacle-b 7.5,2.5,5
```

目标默认从 `[-11, 11] x [-11, 11] m` 采样，与无人机当前实际位置至少相距 `5 m`，
并避开全部 a、b 柱。默认目标安全间距为 `2.55 m`：`1.4 m` 紧急距离、
`1.0 m` 到达半径和约 `0.15 m` 柱半径之和。到达目标后以
`done_reason=goal_reached` 成功终止；局部 `avoidance_complete` 按满足重新武装条件的事件发放奖励，
不会提前结束整集。航点速度默认 `1.02 m/s`。每集路径长度决定实际步数预算，预算相对
原配置放宽 50%，但不会超过 `--max_steps` 上限（默认 `450`）。环境以 `0.1 s`
为动作周期，路径步数预算会按该周期换算。

## 训练产物

每次运行默认创建独立的 `training_runs/dqn_<时间>/` 目录：

- `config.json`：命令行、随机种子、超参数和实际环境参数（含观察/奖励版本、经验回放类型）。
- `training_log.csv`：含探索动作的训练指标。
- `evaluation_log.csv`：固定 `epsilon=0`，且不更新网络或回放缓冲区；除单次评估指标外，
  还记录最近 `eval_window`（默认 3）次评估的滚动成功率/碰撞率/超时率/平均奖励及实际窗口长度，
  以及各终止原因计数（`termination_reasons`，JSON）。
- `step_log.csv`：逐步级日志（动作、奖励、终止原因、障碍距离、偏移量等）。
- `best_model.pt`：按滚动指标字典序选择的最佳评估模型——依次比较滚动成功率、碰撞率、
  超时率（越低越好）、平均奖励；无有效评估 episode 时不会保存为最佳。
- `last_model.pt`：最后状态；正常结束、重置失败中止和 Ctrl+C 都会保存。
- `status.json`：结束状态、完成 episode 数和总训练步数。

通过 `start_sim.sh --training` 启动时，`config.json` 还会记录障碍物坐标、轨迹类型和飞行高度。

根目录旧的 `model.pt` 和 `training_log.csv` 属于旧版流程，不会被新训练读取或覆盖。
测试策略时优先使用同一运行目录中的 `best_model.pt`，并结合
`evaluation_log.csv` 确认它对应的评估结果。

当前环境使用 22 维观测和 6 个动作。22 维观测组成为：12 维扇区最小距离
（旋转到轨迹运动方向）+ 归一化位置 3 维 + 归一化跟踪误差 1 维 + 上一步动作
one-hot 6 维。动作分别为沿原路径、左移、右移、左移并上升、右移并上升、上升悬停；
横向幅值按障碍距离在 `0.3-1.7 m` 间缩放并经过低通平滑。
旧版 16 维/6 动作和 21 维/5 动作模型与此结构不兼容，需要重新训练。

DQN 实现细节：Dueling Q 网络（共享特征层 + value/advantage 分流，隐藏层维度可通过
`--hidden-dims` 配置，默认两层 `128,128`）、
Double DQN 目标、优先经验回放（PER，`alpha=0.6`、`beta=0.4`、容量 100000）、
SmoothL1 损失、Adam 优化器。默认超参数：学习率 `1e-4`、折扣因子 `gamma=0.99`、
batch size `64`、目标网络同步周期 `500` 步、训练起始步数 `1000` 步；
学习率余弦退火调度默认关闭（`--use-lr-schedule` 显式启用）。

当前密集障碍版本使用 33 维观测：12 个运动坐标系 LiDAR 扇区、位置/跟踪误差、
机体速度与参考速度、当前局部偏移、前/左/右净空变化率、路径横向误差和上一动作。
旧 22 维 checkpoint 与此输入结构不兼容，需要重新训练。奖励使用动作扫掠区域净空、
TTC、净空变化和 A* 折线路径进度；避障事件离开危险区连续 3 步即结算，不再等待
跟踪误差同时恢复，也不再要求向目标推进 2 m 才能识别下一危险簇。

局部动作默认保持 4 个环境步以抑制 0.1 s 级抖动。速度控制按
前向风险分层：3.0 m 外正常飞行，3.0～2.4 m 以 0.6 倍速预警，2.4～1.4 m
以 0.3 倍速侧移通过；1.4 m 内同样保持 0.3 倍速，不会暂停或反向回退。
训练默认使用 3-step return，并以逐样本 TD error
更新 PER；`--curriculum` 可启用短路径、中路径、全目标范围三阶段课程。

评估同时报告普通成功率、安全成功率（到达且全程未进入 0.6 m 风险区）、碰撞率和
风险区进入率。最佳模型首先比较更低碰撞率，然后比较安全成功率、风险区进入率和
普通成功率，避免保存“到达更多但碰撞更多”的策略。

正式对比应至少使用 3 个 seed，例如分别运行 `--seed 42`、`--seed 43`、`--seed 44`，
并汇总安全成功率与碰撞率的均值和标准差。训练日志额外记录 A/B 障碍遭遇步数、
A/B 最近障碍归因的碰撞事件、实际飞行距离和每米碰撞事件，便于区分已知规划障碍与
未知感知障碍的表现。
训练中每次贪心评估默认 30 个 episode；独立评估（`evaluate_policy.py`）默认 50 个 episode。
旧 checkpoint 只有在网络结构一致时才能加载（用与训练时相同的 `--hidden-dims`）。

经验证推荐的环境配置：`tracking_error_weight=0.1`（已是默认值）。200 集对比实验中它使训练期
滚动成功率中位数从 0.32 提升到 0.74、消除 0% 崩塌评估，best_model 独立评估 100% 成功/0% 碰撞，
且动作分布均衡（旧默认 0.01 训练出的 best 是 91% 单一动作的模态塌缩策略）。

6 杆对称场景（`-3,-3,5;3,3,5;3,-3,5;-3,3,5;6,0,5;-6,0,5`）200 集对比实验结论：
- `min_offset_xy=0.05`（V2）：6 杆独立评估 100% 成功/0% 碰撞、训练期滚动 56.7%（默认 0.3 为 98%/2%、16.7%），
  但固定 2 杆场景退化（独立评估 52%，默认 0.3 为 100%）→ **不做默认值**，如需 6 杆专用可注入：
  `rosparam set /gazebo_env/min_offset_xy 0.05`。
- `max_offset_xy=2.0`（V3）被否决（6 杆独立评估仅 26%，大幅横摆在密集杆场撞向相邻杆且回中更慢），保持默认 1.7。
- 跨场景默认配置（tracking 0.1 / min_offset 0.3 / max_offset 1.7）双场景达标：固定 100%、6 杆 98%。
推荐 6 杆训练协议：`--episodes 200 --eval-interval 50 --eval-episodes 20`。

以上参数支持经 `/gazebo_env/*` 路径覆盖（未覆盖时用默认值），后续实验可直接注入：

```bash
rosparam set /gazebo_env/tracking_error_weight 0.2
python3 src/rl_obstacle_avoidance/scripts/train_dqn.py
```

## 指标语义

`done_reason=timeout` 只表示跑满了最大步数，不等同于成功。只有同时满足以下条件，
环境才会立即以 `done_reason=avoidance_complete` 结束，并把训练日志记为 `success`：

1. 本回合曾进入 `2.4 m` 避障区，确认确实遇到过障碍；
2. 障碍距离随后恢复到 `2.4 m` 以外；
3. 安全距离连续保持 3 步。

goal mode 到达目标只发放 `~goal_reached_reward = +8`，避免安全直达路线仅靠高额终点奖
压过真正的避障表现。每集第一次完整避障发放 `8～18` 分：基础奖励
`~avoidance_event_reward = +8`，质量奖励最多 `~avoidance_quality_bonus = +10`。
质量分中 75% 来自本次避障最低净空：保持在 `1.4 m` 紧急距离之外得满分，接近
`0.6 m` 碰撞线时降至零；25% 来自避障结束时的轨迹恢复误差。事件必须在重新达到
`2.4 m` 净空且连续稳定 3 步后结算。goal mode 每集最多结算 5 次；离开一个危险簇后
再次进入避障区即可开始新事件。
非 goal mode 完成避障还会发放 `~avoidance_success_reward = +4` 的终止奖励。
进入 `0.6 m` 碰撞风险区即以 `collision` 终止。碰撞终止、发散、低高度和超时会再扣除
`~terminal_failure_penalty`（默认 `-20`）。
开局一直无障碍不会触发成功奖励，恢复过程中再次靠近障碍会重新累计连续安全步数。

默认距离配置为：LiDAR 最小量程 `0.4 m`、碰撞风险 `0.6 m`、紧急距离
`1.4 m`、避障距离 `2.4 m`、预警距离 `3.0 m`。A* 对已知 a 柱仍使用独立的
`1.8 m` 规划安全边距；
动作风险由前方 `±60°` 净空触发，后方障碍不会错误禁止直行；左右侧净空会分别屏蔽
受阻方向。清晰区只允许沿原路径，预警区只允许直行或水平侧移，避障区允许带上升的
侧移动作；只有紧急区两侧均受阻时才允许“上升悬停”。
曲线路径额外使用默认 `2.0 s` 的轨迹前视：LQR 发布半程和终点切线，环境按半个
LiDAR 扇区的角度间隔扫描两段航向变化，并与无人机实际速度方向合并。这样连续折线、
S 弯和跟踪滞后时，位于未来路径走廊但尚不在当前切线正前方的障碍也会进入动作掩码。
启动时会检查这些阈值的顺序；碰撞阈值落入
LiDAR 盲区时训练会直接报错，不再生成无效日志。

点云特征超过 `0.5 s` 未更新时按感知超时终止 episode，避免策略继续使用积压的旧帧。
`0.4 m` 最小量程用于过滤无人机机体回波，同时保留 `0.4～0.6 m` 碰撞观测区。训练器还会
在第 20 个 episode 检查累计环境步数；若少于 100 步，会以
`aborted_invalid_environment` 中止，而不是把未更新的随机模型标记为训练完成。
reset 清零局部偏移后，会等待轨迹误差恢复且 360 度净空达到 `2.4 m`。goal mode
从无人机稳定后的实际位置采样目标并规划路径。正式路径发布后只等待
新的观测，不会在等待轨迹贴合时消耗本集路径。近障碍表示环境尚未准备好，不会立即把它
误记为 reset 故障；只有等待超时后才记录失败。
每次正式 episode 路径发布前，还会等待无人机水平速度降到 `0.15 m/s` 以下，并在
单点保持位置的 `0.20 m` 范围内稳定连续 10 条速度观测；该保持位置会作为 A* 路径的
精确首航点。
单点稳定或规划失败时环境内部默认重试 2 次；只要一次 reset 校验失败，训练器
就中止本轮训练并将具体失败阶段写入 `reset_failure_reason`，避免继续使用失配的
飞行器状态污染后续场景。

目标模式的步进奖励基于无人机到真实目标点的距离变化，不再误用 LQR 跟踪误差。
基础净奖励默认为 `+0.01/步`，障碍接近惩罚随距离增加至 `0.5/步`，
因此危险区内不会再出现正的生存奖励。这是 reward version 6，应从新 replay buffer 重新训练。
`training_log.csv` 记录本集的 `avoidance_quality` 和 `avoidance_reward`，`step_log.csv`
中的 `avoidance_reward_step` 只在实际结算避障事件的那一步非零。

训练表现包含 epsilon-greedy 探索，不能用于判断最终策略。以
`evaluation_log.csv` 的 `success_rate`、`collision_rate` 和
`timeout_rate`、`mean_min_obstacle` 为主要判断依据。
