## 三、执行与成果口径

1. 先完成 N0 以固定可信基线。N1/N2 使用同一观测接口设计；**先建立视场门控场景，再评价跟随能否防止失去目标**。N3/N4 可独立推进，最后与 N1/N2 合并回归 M3–M6。N5 是性能深化，N6 是视觉交付。
2. 每项在 run 前锁定场景、参数、种子和代码/场景/模型哈希；分别报告名义、故障注入、基础设施失败，并保持 `attempted = valid_task + infra_failure + aborted`、`valid_task = tracking_success + mission_failure`。固定样例 4/4 和 51/51 不代表总体成功率。
3. 阶段 A `TRACKING_SUCCESS` 仅指**地面车抵近并持续近距跟踪**。无拦截机构，`INTERCEPT_CONFIRMED` 禁用；无人机跟随目标不替代地面任务终态。
4. 原 M0–M7 文档保留历史批次；新增能力另附验收文档，注明旧证据受影响范围及新批次。接口、阈值与定稿由本工作区负责人独立决策，以可核查证据验收。
