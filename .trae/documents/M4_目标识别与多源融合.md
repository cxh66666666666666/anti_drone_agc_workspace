# M4 目标识别与多源融合 —— 实施计划

## Context（为什么做）

任务清单 M4（P1）要求：**接入目标识别与多源融合**，负责接入、超时/失联处理与端到端日志；交付"目标/障碍消息含来源、坐标系、时间戳、置信度；融合结果可被 M3 消费；注入延迟、丢失和冲突观测时有可解释行为"。

现状：`/agc/targets` 只有真值适配器 `gt_adapter` 一个源（M0 契约 v1.1 冻结），无感知前端、无融合、无障碍观测消息；目标跟随与障碍避障均由场景静态配置直接驱动。M4 需补齐多源观测→融合→同一 `/agc/targets`/`/agc/obstacles` 输出，并被 M3 规划链路消费，同时保证 M1–M3 既有证据（gt_adapter + 场景障碍路径）不受影响。

**用户已定稿的取舍**：① 目标+障碍全链路融合并接入规划；② 升 M0 契约为 v1.2 正式登记观测接口；③ 延迟/丢失/冲突用在线 rosparam 可调 + Python 脚本按时序注入；④ 实时链路 C++、离线工具 Python；⑤ 无头仿真。

**诚实口径**：本阶段感知仍是"由 Gazebo 真值派生的感知仿真"，不是真实视觉识别；M4 文档须显式标注，不得宣称完成真实目标探测。

## 设计核心原则

1. **感知驱动规划、真值裁判安全**：融合障碍只喂 `map_adapter`/`ground_planner` 的避障动作；**净空/碰撞/紧急判据（`task_manager`）坚持真值场景几何**，避免漏检掩盖真碰撞、虚警造假失败污染 `valid_task_runs`。
2. **source=scenario 构造性等价**：老路径代码不被改动，消费者仅在障碍源被激活时改走融合集，保证 M1–M3 证据不受影响。
3. **相关噪声保守融合**：各通道源自同一真值、误差相关，逆方差加权会虚假缩小协方差；改用"每通道独立 RNG + 独立偏置/延迟 + 保守协方差（取 max/加共同误差项）"，并在 v1.2 写明相关性假设。
4. **不刷新旧观测时间**：无新有效观测即发空数组，绝不复制旧姿态换新 stamp。

## 一、接口升级（契约 v1.2）

新增 `docs/项目任务日志/M0/M0_接口契约_v1.2.md`（在 v1.1 基础上追加"感知与融合"一节），登记：

新增消息（`src/air_ground_core/msg/`）：
- `TargetObservation.msg`：`Header header`(观测时刻, frame=world)、`string target_id`、`string sensor_id`、`PoseWithCovariance pose`、`float32 confidence`、`uint32 obs_seq`
- `ObstacleObservation.msg`：`Header header`、`string obstacle_id`、`string sensor_id`、`PoseWithCovariance pose`、`geometry_msgs/Vector3 size`、`float32 confidence`、`uint32 obs_seq`
- `SensorObservation.msg`：`Header header`、`string sensor_id`、`TargetObservation[] targets`、`ObstacleObservation[] obstacles`
- `AirObservationArray.msg`：`Header header`、`SensorObservation[] sensors`
- `ObstacleTrack.msg`：`Header header`、`string obstacle_id`、`geometry_msgs/Pose pose`、`geometry_msgs/Vector3 size`、`float32 confidence`、`string source`
- `ObstacleTrackArray.msg`：`Header header`、`ObstacleTrack[] tracks`

新增话题：
| 话题 | 类型 | 唯一发布者 | 频率/年龄 |
| --- | --- | --- | --- |
| `/agc/air/obs` | `AirObservationArray` | `air_perception` | 20 Hz，age ≤0.3 s |
| `/agc/obstacles` | `ObstacleTrackArray` | `air_fusion`（激活时） | 10 Hz，无目标发空数组 |

`/agc/targets` 发布者随 `/agc/target/source` ∈ {`gt_adapter`,`air_fusion`} 在 run 前固定；新增 `/agc/obstacles/source` ∈ {`scenario`,`air_fusion`}。同步更新 `agc_params.yaml` 的 `contract_version=agc-m0-v1.2`。

## 二、实时链路节点（C++）

- **新增 `air_perception`**：读 `/gazebo/model_states` 真值（`intruder_uav` + `pole_1/pole_2`），按 `/agc/perception/sensors` 定义的 N 个通道（建议 2 个：如 `air_eo_front`、`air_ir_top`）独立加噪/延迟/丢包/离群偏置，发 `/agc/air/obs`；每通道独立 RNG + 独立偏置。故障在线可调：`/agc/perception/fault/<sensor>/{enabled,drop_prob,latency_s,outlier_bias_m}`。落 `perception_log.jsonl`。
- **新增 `air_fusion`**：订阅 `/agc/air/obs`；门控：新鲜度（`/agc/fusion/target_max_age_s` 取 **0.35 s**，严于消费者 0.5 s）、置信度（分源阈值）、空间一致性（与当前估计超 `/agc/fusion/gate_m` 判离群并记录原因）。
  - 目标：仅对 inlier 逆方差加权（相关噪声下协方差保守化）；输出 `/agc/targets`（`source=air_fusion`，`header.stamp`=最新真实观测时刻）；无有效观测发空数组。
  - 障碍：按 `obstacle_id` 关联 inlier，取**并集 + 保守外扩**（yaw 环绕与矩形加权无定义，不做加权平均）→ `/agc/obstacles`。
  - 写 `/agc/fusion/*` 诊断参数；落 `fusion_log.jsonl`（输入观测、门控决策、离群标记、融合输出、拒收原因）。
- **改 `gt_adapter`**：仅当 `/agc/target/source==gt_adapter` 时 advertise `/agc/targets`（避免与 air_fusion 双发布者）。
- **改 `map_adapter`**：`/agc/obstacles/source==air_fusion` 时订阅 `/agc/obstacles`，障碍格由融合障碍并集重建（地图几何仍取场景 map 段）；带内容哈希门限防重规划风暴。`scenario` 时构造期行为不变。
- **改 `ground_planner`**：`air_fusion` 时用融合障碍做 OBB 精膨胀；`scenario` 时仍用场景障碍（现状）。
- **`task_manager` 不改安全判据**（真值裁判安全）；仅在 v1.2 写明分工。
- **改 `agc_run_logger`**：`target_source` 改为读参数（删 451/887 硬编码），`meta.json` 增 `obstacle_source` 与 confidence 标定引用，`CONTRACT_DOC` 指向 v1.2，`procKeywords` 增 `air_perception`/`air_fusion`。

## 三、配置 / launch / 脚本

- `agc_params.yaml`：新增 `perception`（sensors 列表、obs_hz、故障默认值）、`fusion`（门限、gate、分源 confidence_min、obstacle_match）、`calibration.confidence_tolerance_m`（建议 0.5 m）。
- `agc_collab.launch`：新增 `target_source`/`obstacle_source` 两个 arg（有默认值，避免未定义 arg 报错）；由 launch **单一设置** `/agc/target/source`、`/agc/obstacles/source`；用 `<node if="$(arg ...)">` 条件包含 `gt_adapter` vs（`air_perception`+`air_fusion`）。默认 `gt_adapter`/`scenario`，M1–M3 重跑进程清单不变。
- `scripts/start_agc_collab.sh`：新增 `--target-source`/`--obstacle-source`，透传给 launch；`PROC_NAMES` 增两节点。
- `CMakeLists.txt`：注册新消息与新可执行节点。

## 四、离线工具与注入（Python，非实时链路）

- `scripts/m4_inject.py`：按时间线用 rosparam 切换 `/agc/perception/fault/<sensor>/*`（延迟/丢包/离群），把注入事件落盘到批跑目录。
- `scripts/verify_fusion.py`：读 run 日志核验——① 消息含 source/frame/stamp/confidence；② 融合结果可被 M3 消费（goal 跟随、状态结算）；③ **延迟**注入后观测 age 超限被判旧、输出 stamp 不刷新；④ **丢失**后 ≤容忍窗发空数组→停车/`TARGET_LOST`；⑤ **冲突**时离群通道被门控拒收、融合跟随 inlier、不做跨源取最大；⑥ confidence 标定：用真值算经验覆盖 P(|err|≤tol) 与声明值一致性。
- `scripts/audit_interfaces.py`：`/agc/targets` 期望发布者改为读参数；按 source 追加 v1.2 话题期望；区分 nominal/fault 核查模式（注入使 age 超限时不计 FAIL）。

## 五、证据与文档

- 证据批次 `experiments/agc_runs/_m4_batch_*`：nominal、latency、loss、conflict、obstacle-fusion 各若干 attempt；注入 run 打 tag 并**排除出成功率分母**。
- 验收文档 `docs/项目任务日志/M4/M4_目标识别与多源融合验收_v1.md`（诚实标注真值派生的感知仿真）。
- 仓库约定 Spec 三件套 `.trae/specs/implement-agc-m4-fusion/{spec.md,tasks.md,checklist.md}`。

## 建议实施顺序

1. 写 Spec 三件套 → 2. 契约 v1.2 + 消息 + CMake → 3. `air_perception` + `air_fusion` → 4. launch/脚本/logger/audit 接线 → 5. 障碍接入 map_adapter/ground_planner（scenario 等价校验）→ 6. 注入脚本 + 核验工具 → 7. 跑证据批次 → 8. 验收文档。

## 验证方式

- `catkin_make` 后按 `--target-source gt_adapter --obstacle-source scenario` 跑基线：`any_leftover=false`、audit PASS、`/agc/targets` 发布者仍为 `gt_adapter`，与 M2/M3 结论一致（回归）。
- 按 `--target-source air_fusion` 跑 nominal：`/agc/targets.source=air_fusion`、M3 因果闭环仍成立（goal 跟随、状态结算）。
- 依次跑 latency/loss/conflict 注入批：`verify_fusion.py` 全项 PASS；`audit_interfaces.py` 在 fault 模式通过。
- obstacle-fusion 批：`/agc/obstacles` 非空且被 map/planner 消费（规划日志含融合障碍几何），`task_manager` 净空仍用真值。
